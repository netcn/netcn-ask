HTTP/3 为什么要从 TCP 换成基于 QUIC 的 UDP？

Why does HTTP/3 move from TCP to UDP-based QUIC?

传统 HTTP/2 仍跑在 TCP 上，队头阻塞和一次丢包会拖慢整个连接；QUIC 在 UDP 之上自建可靠传输，把多个请求流独立多路复用，且支持 0-RTT 快速握手与连接迁移。IETF 在 2021 年发布 RFC 9000 将其标准化。
HTTP/2 still runs over TCP, where head-of-line blocking and one lost packet stall the whole connection; QUIC builds its own reliable transport over UDP, multiplexing independent streams, with 0-RTT handshakes and connection migration. The IETF standardized it as RFC 9000 in 2021.

分组交换比传统的电路交换更适合计算机通信在哪？

Why does packet switching suit computer communication better than circuit switching?

电路交换要先建立一条独占的端到端线路，空闲也占用资源；分组交换把数据切成小包、各自独立路由、在目的地重组，链路被多用户统计复用，更适合突发、不连续的计算机流量。Kleinrock 与 Baran 在 1960 年代奠定了其理论。
Circuit switching reserves a dedicated end-to-end line even when idle; packet switching chops data into small packets routed independently and reassembled at the destination, statistically multiplexing the link—better for bursty computer traffic. Kleinrock and Baran laid the theory in the 1960s.

TCP 拥塞控制的基本思路是什么？

What is the basic idea of TCP congestion control?

发送方用拥塞窗口随 ACK 增长（慢启动、拥塞避免），丢包时减半窗口（或快速重传）以退避，从而在共享网络中动态逼近可用带宽而不压垮链路。
The sender grows a congestion window on ACKs (slow start, congestion avoidance) and cuts it on loss (or fast retransmit) to back off, dynamically approaching available bandwidth without overwhelming the link.

TCP 和 UDP 有什么区别？各自适合什么场景？

What is the difference between TCP and UDP, and when is each used?

TCP 是面向连接的可靠传输：三次握手建立连接，靠序号、确认和重传保证数据不丢不乱序，还有拥塞控制，代价是额外开销和延迟。UDP 无连接、不保证送达，只管快速发出去。网页、文件传输、邮件用 TCP；视频通话、在线游戏、实时音视频用 UDP（或基于 UDP 的 QUIC）。
TCP is connection-oriented and reliable: a three-way handshake opens the connection, while sequence numbers, acknowledgments, and retransmission prevent loss and reordering, plus congestion control—at the cost of overhead and latency. UDP is connectionless and best-effort, just sending packets fast. Web pages, file transfers, and email use TCP; video calls, online games, and streaming media use UDP or QUIC built on it.

什么是网络拥塞控制？

What is network congestion control?

拥塞控制让发送方根据网络丢包和延迟动态调整发送速率，避免过多数据淹没网络造成崩溃，TCP 的慢启动和拥塞避免是典型例子。
Congestion control makes senders adjust their rate based on loss and delay to avoid overwhelming the network; TCP slow start and congestion avoidance are classic examples.

TCP/IP 协议栈是怎样让异构网络互联的？

How does the TCP/IP stack interconnect heterogeneous networks?

Cerf 与 Kahn 在 1974 年设计的分层协议用 IP 做无连接、尽力而为的寻址与路由，TCP 在其上提供可靠、有序、流量可控的字节流。这种『端到端』思想使不同物理网络能无缝拼接成今天的互联网。
The layered protocol Cerf and Kahn designed in 1974 uses IP for connectionless, best-effort addressing and routing, with TCP on top adding reliable, ordered, flow-controlled byte streams. This end-to-end principle let disparate physical networks stitch into today's Internet.

SYN 洪泛攻击利用了 TCP 握手的什么弱点，SYN cookie 怎么化解？

What weakness in the TCP handshake does a SYN flood exploit, and how do SYN cookies defeat it?

服务器收到 SYN 后必须为这个半开连接分配一条待完成连接记录（保存序号、选项等）并回 SYN-ACK，然后等待第三个包；攻击者用伪造源地址狂发 SYN 而从不回 ACK，很快占满有限的半连接队列，合法请求随之被丢弃。SYN cookie 让服务器不保存状态：把时间戳、MSS 索引和四元组的带密钥哈希编码进 SYN-ACK 的初始序号，只有客户端返回正确确认号才能验证这份票据，此时才真正建立套接字。代价是丢失部分 TCP 选项且需要额外哈希计算，因此内核通常只在队列即将溢出时启用。
On receiving a SYN the server must allocate a half-open connection record holding sequence numbers and options, send a SYN-ACK and wait for the third packet; an attacker sprays SYNs from spoofed addresses and never replies, filling the finite backlog queue so legitimate connections get dropped. SYN cookies remove that state: the server encodes a timestamp, an MSS index and a keyed hash of the connection tuple into the initial sequence number it sends, and only an ACK carrying the right acknowledgement number proves the ticket, at which point the socket is really created. The trade-offs are lost TCP options and extra hashing, so kernels usually enable cookies only as the backlog nears overflow.

路由器是怎么决定把数据包往哪送的？

How does a router decide where to forward a packet?

路由器按“逐跳转发”工作：每个路由器维护一张路由表，用目的地址的最长前缀匹配查表，把包交给下一跳。路由表可以由管理员静态配置，也可以由 OSPF、BGP 等路由协议动态交换信息生成，综合考虑跳数、带宽和策略。数据包每经过一跳，路由器都要重新查表决定方向。
Routers work hop by hop: each router keeps a routing table, matches the destination's longest prefix, and hands the packet to the next hop. Tables are configured statically by operators or built dynamically by protocols such as OSPF and BGP that exchange reachability info weighing hops, bandwidth, and policy. At every hop the router consults the table again to pick the direction.

Wi-Fi 信号显示满格，为什么网速还是很慢？

Why can Wi-Fi be slow even when the signal bars are full?

信号格只反映接收到的信号强度，不代表可用带宽。Wi-Fi 是共享介质，所有设备用 CSMA/CA 轮流抢同一个信道，邻居的路由器占用重叠信道会让大家互相退避；2.4 GHz 只有 1、6、11 三个互不重叠的 20 MHz 信道，公寓楼里极易拥塞。此外隐藏节点导致的碰撞、旧设备以低速率长时间占用空口，都会拉低整体吞吐，而真正的瓶颈也常在宽带线路或对端服务器上——这些都不体现在信号格里。
The bars report received signal strength, not available throughput. Wi-Fi is a shared medium in which every device takes turns under CSMA/CA, so neighbouring access points on overlapping channels force everyone to back off, and the 2.4 GHz band offers only three non-overlapping 20 MHz channels, numbers 1, 6 and 11, which saturates fast in an apartment block. Hidden-node collisions and legacy clients that hog airtime at low data rates drag the whole cell down as well, and often the real bottleneck is the broadband line or the remote server, none of which the bars can show.

输入网址后，DNS 是怎么找到对应服务器的？

How does DNS find the server behind a web address?

浏览器先查本地缓存，再向递归解析器询问；解析器从根域名服务器开始，按“顶级域（如.com）→ 权威服务器”逐级下查，最终得到目标IP。整个过程本质上是把人好记的域名翻译成机器使用的IP地址，通常要经多级缓存加速。
The browser checks its local cache first, then asks a recursive resolver, which walks down from root servers through top-level domains (such as .com) to the authoritative server to obtain the target IP. Essentially DNS translates human-friendly names into the IP addresses machines use, with caching at several levels to speed it up.

子网掩码（subnet mask）是干什么用的？

What is a subnet mask used for?

子网掩码是一串和 IP 等长、前面全 1 后面全 0 的数，用来把 IP 地址切成“网络号”和“主机号”两部分。路由器借此判断目标是否在本地子网，从而决定直接送达还是交给上层网关转发。
A subnet mask is a same-length number of leading 1s then 0s that splits an IP into network and host parts. Routers use it to tell whether a destination is local, deciding to deliver directly or forward to a gateway.

网络延迟为什么不可能无限降低，北京到纽约的 ping 值有物理下限吗？

Why can't network latency be reduced indefinitely — is there a physical floor on the ping from Beijing to New York?

有，下限由光速和线路实际长度决定。光在单模光纤里因折射率约 1.47 只能跑约 20 万公里每秒，而北京到纽约的海缆路径超过一万公里，单程就要约 55 毫秒，往返 110 毫秒以上，这部分无法用增加带宽或换设备消除。实测 ping 通常更高，因为路由要绕行登陆站和交换节点，每一跳还叠加排队与转发时延。这也是为什么修建更直的新海缆、在本地部署边缘节点，比单纯加带宽更能改善体验。
Yes — the floor is set by the speed of light and the actual path length. Light travels at about 200,000 km/s in single-mode fibre because the core's refractive index is roughly 1.47, and the submarine route from Beijing to New York exceeds 10,000 km, so one way costs about 55 ms and a round trip more than 110 ms, which no amount of bandwidth or faster hardware removes. Measured pings run higher still because routes detour through landing stations and exchange points, each hop adding queueing and forwarding delay. That is why straighter new cables and local edge nodes improve experience more than simply buying bandwidth.

为什么要从 IPv4 升级到 IPv6？

Why is the internet upgrading from IPv4 to IPv6?

IPv4 地址只有32位，理论最多约43亿个，早已不够给每个联网设备分配唯一地址，主要靠 NAT 变通。IPv6 把地址扩展到128位，可分配数量近乎无限，还简化了报文头部、内建安全性并支持更好的移动性。全球设备数仍在增长，IPv6 是长期出路。
IPv4 has only 32-bit addresses, at most about 4.3 billion—nowhere near enough for every connected device, which is why NAT papers over the shortage. IPv6 extends addresses to 128 bits, an effectively endless pool, while simplifying headers, building in security, and improving mobility. With device counts still growing, IPv6 is the long-term answer.

Why do REST-style web APIs use HTTP verbs to act on resources?

REST 把每个数据对象看作一个带 URL 的资源，用 GET/POST/PUT/DELETE 等标准方法表达增删改查，状态由服务器保存、请求自描述。Fielding 在 2000 年的博士论文中系统提出这一架构风格，使接口统一且易扩展。
REST treats each data object as a URL-addressed resource and uses standard verbs GET/POST/PUT/DELETE for CRUD, with state kept server-side and requests self-descriptive. Fielding formalized this architectural style in his 2000 dissertation, yielding uniform, scalable interfaces.

什么是 MAC 地址？

What is a MAC address?

MAC 地址是烧在网卡上的硬件编号，用于在同一个局域网内识别设备，和用于广域网寻址的 IP 地址不同。
A MAC address is a hardware number burned into a network card to identify devices on a local network, unlike an IP address used for wider routing.

NAT 是怎么让家里十几台设备共用一个公网 IP 的？

How does NAT let a dozen home devices share a single public IP address?

家用路由器转发出站数据包时，把源地址从私有地址（例如 192.168.1.7）改写成自己的公网地址，同时把源端口换成一个唯一的新端口，并在转换表里记下这条映射。回包按目的端口查表还原成对应的内网地址和端口，因此多台设备可以复用同一个 IP，这种带端口复用的形式称为 NAPT。副作用是外部无法主动连入内网，需要端口转发、UPnP 或 STUN/TURN 打洞，点对点应用因此变复杂。
As an outbound packet leaves the LAN, the router rewrites its source address from a private one such as 192.168.1.7 to the router's own public address and replaces the source port with a unique new value, recording the mapping in a translation table. Reply packets are matched by that destination port and rewritten back to the correct internal host and port, so many devices multiplex one address — the port-multiplexing variant is called NAPT. The side effect is that outsiders cannot initiate connections inward without port forwarding, UPnP or STUN/TURN hole punching, which complicates peer-to-peer applications.

路由器和交换机有什么区别？

What is the difference between a router and a switch?

交换机在局域网内基于 MAC 地址在二层转发，连接同一网段设备；路由器基于 IP 地址在三层转发，连接不同网络并决定跨网路径。
A switch forwards by MAC address at layer 2 within a LAN; a router forwards by IP at layer 3 between networks and decides cross-network paths.

网络为什么要分层（如TCP/IP模型）？

Why is networking organized in layers (like the TCP/IP model)?

分层把网络通信拆成应用、传输、网络、链路等独立层次，每层只负责自己的任务，并只依赖下一层提供的接口。这样上层不用关心数据具体怎么传输，下层升级换代不影响上层，整个系统才能让几十亿设备互通。
Layering splits communication into independent levels—application, transport, internet, link—each handling its own job and using only the interface below. Upper layers need not care how data physically travels, and upgrading lower layers does not break upper ones, which is how billions of devices interoperate.

网络明明没有坏,为什么一拥而上反而集体变慢?拥塞控制如何自救?

Nothing is broken, yet everyone slows down together — how does congestion control rescue a crowded network?

路由器缓冲区有限,注入速率超过瓶颈链路出口时排队延迟飙升直至溢出丢包;重传还会加倍流量,酿成拥塞崩溃。雅各布森1988年为TCP设计的方案成为教科书:各发送方加法增大窗口,侦测到丢包就乘性减半(AIMD),无需中心调度,仅凭端到端信号便收敛到公平分享带宽。后续BBR改用实测带宽与时延积建模,在高丢包无线网上更稳健,思想同源:把拥堵当反馈信号而非故障。
Router buffers are finite: when offered load exceeds a link's exit rate, queueing delay soars until drops begin, and retransmissions double traffic into collapse. Jacobson's 1988 TCP recipe became the textbook answer: each sender probes by growing its window additively, cuts it in half upon loss, then climbs again — additive increase, multiplicative decrease — converging to fair shares without any central scheduler, pure emergent order from end-to-end signals. Modern BBR instead models measured bandwidth times delay, thriving on lossy wireless; same philosophy: treat congestion as feedback, not failure.

DNS 为什么被称为互联网的『电话簿』？

Why is DNS called the Internet's phone book?

DNS 把人类易记的域名翻译成机器使用的 IP 地址，靠分布式的层级服务器（根、顶级域、权威）逐级解析。Mockapetris 在 1983 年设计这一系统，避免了全网维护一张巨型对照表。
DNS translates human-friendly domain names into machine IP addresses via a distributed hierarchy—root, top-level, and authoritative servers—resolved step by step. Mockapetris designed it in 1983, avoiding one giant global lookup table.

HTTP 是无状态的，网站怎么记住“你”？

HTTP is stateless—how do websites remember you?

服务器可以在响应里带一个小数据块 Cookie，浏览器自动保存并在下次请求时原样带回，服务器据此识别会话，购物车、登录状态都靠它。Session 则是服务器端保存的用户状态，靠 Cookie 里的会话ID找到。Cookie 也可能被用于追踪，所以浏览器提供清理和屏蔽功能。
A server can attach a small Cookie to its response, the browser stores it and echoes it back on later requests, letting the server recognize the session—shopping carts and login states rely on this. A session is the server-side state located by a session ID in the cookie. Cookies can also be used for tracking, so browsers offer clearing and blocking.

在浏览器敲下网址到页面出现,这几百毫秒里互联网做了哪些事?

Between typing a URL and seeing the page, what does the internet do in those few hundred milliseconds?

一条完整接力:域名先经 DNS 解析为 IP(缓存未中则逐级询问根、顶级域与权威服务器);TCP 三次握手建连,TLS 握手协商加密并验证证书链;浏览器发出 HTTP 请求取回 HTML;解析中再对 CSS、JS、图片并行发起请求,常经 CDN 就近返回;渲染引擎排版绘制。每一跳靠路由器逐包转发,BGP 决定洲际路径。任一环节慢几十毫秒用户都能感知——这正是性能优化的战场地图。
A full relay: the resolver turns the domain into an IP via DNS (asking root, TLD then authoritative servers on cache miss); TCP performs its three-way handshake for a reliable pipe; TLS negotiates ciphers and validates the certificate chain; the browser sends HTTP and receives HTML; parsing triggers parallel fetches for CSS, JS and images, often served from a nearby CDN edge; finally the engine lays out and paints. Each hop rides router-by-router packet forwarding with BGP quietly choosing intercontinental paths. Tens of milliseconds anywhere in this chain are user-visible — hence the performance battlefield.

BGP 在互联网中扮演什么角色？

What role does BGP play on the Internet?

BGP（边界网关协议）是自治系统之间的路由协议，通过路径向量交换可达性信息，决定跨运营商的流量走向；配置错误或劫持会导致大规模路由异常。
BGP is the inter-AS routing protocol; it exchanges reachability via path vectors to decide cross-ISP traffic paths, so misconfiguration or hijacks cause large-scale routing incidents.
