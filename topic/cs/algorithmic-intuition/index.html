Shor 算法为什么能让量子计算机快速分解大数？它为什么威胁 RSA？

Why does Shor's algorithm let quantum computers factor large numbers fast, and why does it threaten RSA?

Shor 算法把大数分解转化为求模幂函数的周期：量子叠加一次并行计算多个指数值，量子傅里叶变换把振幅集中在周期相关的频率上，测量即得周期，再用周期经辗转相除得到因子。其时间复杂度对位数是多项式，而经典最佳算法（数域筛法）是亚指数的。RSA 的安全性恰恰依赖大数分解困难，因此规模足够的通用量子计算机将破解 RSA。
Shor's algorithm reduces factoring to finding the period of a modular-exponential function: superposition evaluates many exponents at once, the quantum Fourier transform concentrates amplitude at period-related frequencies, measurement yields the period, and the factor follows via the Euclidean algorithm. Its runtime is polynomial in the bit length, versus sub-exponential for the best classical methods like the number-field sieve. Since RSA's security rests on factoring being hard, a sufficiently large universal quantum computer would break it.

快速排序最坏情况下为什么退化到O(n²)？

Why does quicksort degrade to O(n²) in the worst case?

快排的递归深度取决于每次分区是否均衡。如果每次选的基准总是当前区间的最小值或最大值（比如数据已有序而基准固定取端点），分区就完全失衡，一边为空一边剩 n−1，递归 n 层、每层约 n 次比较，总复杂度为O(n²)。随机化选基准或三数取中可以把退化概率压到极低，期望仍为O(n log n)。
Quicksort's recursion depth depends on how balanced each partition is. If the pivot is always the current minimum or maximum—for example sorted input with a fixed-end pivot—the partition becomes completely lopsided, one side empty and the other n−1, recursing n levels with roughly n comparisons each, giving O(n²). Randomized pivot selection or median-of-three makes this so unlikely that expected time stays O(n log n).

为什么基于比较的排序下限是 O(n log n)？

Why is O(n log n) the lower bound for comparison sorting?

任意基于比较的排序，其决策过程可建模为一棵二叉树，n 个元素有 n! 种排列，叶子至少 n! 个。树高至少 log₂(n!) ≈ n log₂ n，因此任何比较排序最坏情况至少 O(n log n)。计数排序等不依赖比较的算法可突破此限。
Any comparison sort can be modeled as a decision tree with at least n! leaves for n! permutations. The tree height is at least log₂(n!) ≈ n log₂ n, so the worst case needs at least O(n log n) comparisons. Non-comparison sorts like counting sort can beat this bound.

为什么说停机问题不可判定？这对"计算机的能力边界"意味着什么？

Why is the halting problem undecidable, and what does that say about the limits of computing?

图灵用对角线法证明：不存在一个程序 H，能对任意"程序+输入"判定其是否停机。假设 H 存在，构造程序 D，让它对自身调用 H：若 H 说 D 会停机，D 就进入死循环；若 H 说 D 不停机，D 就立即停机，产生矛盾。因此停机问题不可判定。这个结果划定了任何编程语言的能力边界，同时丘奇-图灵论题指出一切可计算函数恰好是图灵可计算的。
Turing proved by diagonalization that no program H can decide, for an arbitrary program and input, whether it halts. Suppose H exists; build program D that runs H on itself: if H says D halts, D loops forever; if H says D does not halt, D halts immediately — a contradiction. So the halting problem is undecidable. This result marks the boundary of what any programming language can express, and the Church–Turing thesis states that all computable functions are exactly the Turing-computable ones.

为什么蒙特卡洛方法能给出可靠近似？

Why can Monte Carlo methods give reliable approximations?

蒙特卡洛方法用大量随机抽样来估计难以解析计算的量，依靠大数定律使均值收敛到真实期望。误差通常按 1/√N 下降，所以增加样本能稳步提高精度。它广泛用于积分、物理仿真和金融定价。
Monte Carlo methods use many random samples to estimate quantities that are hard to compute exactly, relying on the law of large numbers to converge to the true expectation. Error typically drops as 1/√N, so more samples steadily improve accuracy. They are widely used in integration, physics simulation, and finance.

随机化算法有什么独特价值？

What unique value do randomized algorithms have?

随机化算法在步骤中引入随机性，往往能用更简单的思路获得平均优秀的表现，例如随机快速排序和哈希。它们能把最坏情况的概率压到极低，或把难解的确定性难题变简单。缺点是需要处理随机源和概率保证。
Randomized algorithms introduce randomness into their steps and often achieve excellent average behavior with simpler logic, like randomized quicksort and hashing. They can make worst cases extremely unlikely or simplify intractable deterministic problems. The trade-off is managing a random source and probabilistic guarantees.

KMP 的 next/前缀函数数组是怎么计算的？为什么总时间能保持 O(m)？

How is KMP's prefix-function (next) array computed, and why does it stay O(m) in total?

前缀函数 π[i] 表示前缀 P[0..i] 的最长相同真前后缀长度。算法从左到右递推，维护当前匹配长度 j：若 P[i]==P[j]，则 π[i]=j+1；否则令 j=π[j−1] 反复回退，直到能匹配或 j=0。因为 j 每步最多加 1，而回退次数受累计增加量限制，所以整个构造是线性的 O(m)。
The prefix function π[i] is the length of the longest proper prefix of P[0..i] that is also a suffix. The algorithm scans left to right, maintaining the current match length j: if P[i]==P[j], π[i]=j+1; otherwise it falls back j=π[j−1] repeatedly until a match is found or j=0. Since j increases by at most 1 per step and the fallbacks are bounded by the total increases, the whole construction is linear, O(m).

Dijkstra 算法是如何求最短路径的？

How does Dijkstra's algorithm find shortest paths?

Dijkstra 算法用于计算非负权图中的单源最短路径。它维护每个节点的当前最短距离，每次从未确定节点中选出距离最小者（用优先队列实现）并“松弛”它的所有邻居——若经该节点更近就更新。贪心选择在非负权下成立：被弹出的节点距离不会再被改善。权值为负时必须改用贝尔曼-福特算法。
Dijkstra's algorithm finds single-source shortest paths in graphs with non-negative edge weights. It keeps the current best distance for each node, repeatedly extracts the nearest unvisited node via a priority queue, and relaxes its neighbors—updating them when a shorter route is found. The greedy choice is valid only for non-negative weights: once a node is popped, its distance can never improve. Negative weights require Bellman–Ford instead.

Grover 搜索算法能带来多大加速？它适合什么问题？

How much speedup does Grover's algorithm provide, and what problems does it fit?

Grover 算法对无结构数据库的搜索，把经典的 O(N) 次黑盒查询降到 O(√N) 次，是二次加速而非指数加速。它通过振幅放大反复"翻转目标态的相位并围绕均值放大"，约 √N 轮后目标态概率接近 1。它对任意黑箱搜索有效，例如把哈希碰撞搜索从 2ⁿ 降到 2^(n/2)，所以对称密码（如 AES）需要加倍密钥长度来维持安全。
Grover's algorithm searches an unstructured database with O(√N) black-box queries instead of classical O(N) — a quadratic, not exponential, speedup. Amplitude amplification repeatedly flips the target state's phase and amplifies around the mean; after about √N rounds the target is found with near-certainty. It works for any black-box search — for example, hash-collision search drops from 2ⁿ to 2^(n/2) — which is why symmetric ciphers like AES need doubled key sizes to stay secure.

动态规划的核心思想是什么？为什么能避免指数级计算？

What is the core idea of dynamic programming, and why does it avoid exponential work?

动态规划利用“最优子结构”把大问题拆成小问题，并保存“重叠子问题”的结果避免重复计算。以斐波那契数列为例，朴素递归会重复计算大量相同子问题，复杂度约O(2ⁿ)；自底向上逐项保存结果后降为O(n)。关键步骤是定义状态、写出转移方程并确定递推顺序。
Dynamic programming exploits optimal substructure—splitting a big problem into subproblems—and stores results of overlapping subproblems to avoid recomputation. Naive recursive Fibonacci recomputes the same subproblems, costing roughly O(2ⁿ); bottom-up memoization brings it down to O(n). The key steps are defining states, writing the transition equation, and fixing the computation order.

什么是 NP 难问题？

What is an NP-hard problem?

NP 难问题指至少和所有 NP 问题一样难的问题，目前没有已知的多项式时间解法。旅行商、布尔可满足性都属于此类。若有人找到其一的高效解法，就等价于解决所有 NP 问题（即 P=NP）。
An NP-hard problem is at least as hard as every problem in NP, and no polynomial-time solution is known. The traveling salesman and Boolean satisfiability are examples. Finding a fast solution for one would mean solving all NP problems efficiently, i.e. P=NP.

P 和 NP 的核心区别是什么？NP 完全问题为什么地位特殊？

What is the core difference between P and NP, and why are NP-complete problems special?

P 是能在多项式时间内求解的问题；NP 是解能在多项式时间内被验证的问题——是"验证"而不是"求解"。显然 P⊆NP，而 P=NP 是否成立仍是悬而未决的猜想。NP 完全问题是 NP 中最难的一类：所有 NP 问题都能多项式时间归约到它，只要多项式时间内解出任何一个 NP 完全问题，P 就等于 NP，所以它成了整个问题的焦点。
P contains problems solvable in polynomial time; NP contains problems whose solutions can be verified in polynomial time — verified, not solved. Clearly P⊆NP, but whether P=NP is still an open conjecture. NP-complete problems are the hardest in NP: every NP problem reduces to them in polynomial time, so solving any single one in polynomial time would imply P=NP — which makes them the focus of the whole question.

什么情况下贪心算法会得出错误结果？

When does a greedy algorithm give a wrong result?

当问题不满足“贪心选择性质”和“最优子结构”同时成立时，局部最优不等于全局最优。例如零钱问题中若面额是 1、3、4，为 6 找零用贪心会取 4+1+1 而非最优的 3+3。此时需用动态规划或搜索。
When a problem lacks the greedy-choice property together with optimal substructure, the local optimum is not the global one. For coin denominations 1, 3, 4, greedy change for 6 picks 4+1+1 instead of the optimal 3+3. Dynamic programming or search is then needed.

Edmonds-Karp 算法如何改进 Ford-Fulkerson？为什么它能保证多项式时间？

How does Edmonds-Karp improve Ford-Fulkerson, and why does it guarantee polynomial time?

Ford-Fulkerson 沿任意路径增广，若容量选择不当甚至可能不终止；Edmonds-Karp 每次用 BFS 找边数最少的增广路。可以证明每次增广后各顶点到源点的最短距离单调不减，增广次数上界为 O(VE)；每次 BFS 开销 O(E)，因此总复杂度 O(VE²)，保证多项式时间终止。
Ford-Fulkerson augments along arbitrary paths and can even fail to terminate with unfortunate capacities; Edmonds-Karp always augments along a BFS-shortest path in terms of edge count. One can prove the shortest distance from the source to every vertex never decreases across augmentations, bounding the number of augmentations by O(VE); each BFS costs O(E), giving O(VE²) in total — a guaranteed polynomial bound.

摊还分析的势能法（potential method）是怎么运作的？动态数组扩容为什么摊还 O(1)？

How does the potential method of amortized analysis work, and why is dynamic-array growth amortized O(1)?

势能法定义一个状态函数 Φ，把摊还代价定义为"实际代价 + 势能变化"。对倍增扩容的动态数组，每次插入的摊还代价约为 3 个单位：普通插入实际代价 1、势能增加 2；扩容那一次实际代价为 n，但势能恰好释放约 n，因此 n 次插入总代价为 O(n)，单次平均 O(1)。
The potential method defines a state function Φ and sets the amortized cost to "actual cost + change in potential". For a doubling dynamic array, each insert has an amortized cost of about 3: a normal insert costs 1 and adds 2 to the potential; the resize costs n but releases roughly n of potential. So n inserts total O(n), that is, O(1) amortized per insert.

生日悖论为什么让哈希冲突比直觉上早得多出现？

Why does the birthday paradox make hash collisions show up far sooner than intuition suggests?

关键在于要比较的是「任意两项相同」，而 n 个元素有 n(n-1)/2 个配对，冲突概率随配对数增长而不是随元素个数增长。把值均匀散布到 m 个桶里，大约 √m 个元素之后碰撞概率就超过一半：365 天里 23 个人就有 50% 概率生日相同，64 位哈希在约 2^32 即 40 多亿个值后就该预期碰撞。这条估计直接决定了安全设计的取值：抗碰撞哈希输出至少要 256 位，随机 UUID 要留 122 位随机才能让实际规模下的碰撞可忽略。
The point is that the event is "some pair matches", and n items form n(n-1)/2 pairs, so collision probability grows with the number of pairs rather than the number of items. Spreading values uniformly over m buckets, the chance of a collision passes one half after roughly the square root of m items: 23 people suffice among 365 birthdays, and a 64-bit hash should be expected to collide after about 2^32, some four billion values. That estimate drives real security choices — collision-resistant digests need at least 256 bits, and random UUIDs spend 122 random bits so collisions stay negligible at practical scale.

洗牌时「随便两两交换若干次」为什么不公平，Fisher–Yates 好在哪？

Why is swapping random pairs many times an unfair shuffle, and what makes Fisher–Yates correct?

公平洗牌要求 n! 种排列等概率出现，而随机交换 k 次能产生的等概路径数是 n 的幂次形式，一般不是 n! 的整数倍，因此某些排列必然偏多或偏少；同理，常见的错误写法是把第 i 位与 0 到 n-1 之间的随机位交换，它给出 n^n 条等概路径，分布同样不均匀。Fisher–Yates 从末尾往前遍历，第 i 步只在 0 到 i 之间取随机下标交换，每种排列恰好对应唯一一条路径，概率精确等于 1/n!，且只需 n-1 次随机数和 O(n) 时间。实现要点是随机上界必须随 i 收缩，写成固定的 0 到 n-1 就是那个经典 bug。
A fair shuffle needs all n! permutations to be equally likely, but k random transpositions generate a count of equally likely paths that is a power of n and generally not a multiple of n!, so some permutations must be over- or under-represented. The common buggy loop, swapping position i with a random index anywhere in 0 to n-1, yields n^n equally likely paths and a measurably skewed distribution. Fisher–Yates walks from the end and at step i draws a random index only within 0 to i, so every permutation corresponds to exactly one path with probability exactly 1/n!, using n-1 random draws and linear time. The detail that matters is shrinking the upper bound with i — leaving it fixed is precisely the classic bug.

“最短路径”问题在现实中指什么？

What does the shortest-path problem mean in practice?

最短路径是在图里找到从起点到终点代价最小的路线，代价可以是距离、时间或费用。Dijkstra 算法处理非负权重，Bellman-Ford 能应对负权重。地图导航和物流调度都依赖这类算法。
The shortest-path problem finds the least-cost route from a start to a target in a graph, where cost may be distance, time, or money. Dijkstra handles non-negative weights, while Bellman-Ford also handles negative ones. Map navigation and logistics rely on these algorithms.

缓存局部性原理是什么意思？

What does the principle of cache locality mean?

缓存局部性指程序倾向于重复访问近期或邻近的数据，分为时间局部性和空间局部性。合理的数据布局和访问顺序能让数据留在高速缓存中，大幅加快执行。算法设计常据此优先顺序访问而非跳跃访问。
Cache locality means programs tend to reuse recent or nearby data, split into temporal and spatial locality. Good data layout and access order keep data in fast cache and speed things up greatly. Algorithms are often designed to access sequentially rather than jumping around.

并查集这种数据结构主要解决什么问题？它支持哪两种核心操作？

What problem does the disjoint-set (union-find) data structure solve, and what are its two core operations?

并查集用来管理一组不相交的集合，支持"查找"（find，判断某元素属于哪个集合、两个元素是否连通）和"合并"（union，把两个集合合并成一个）。它常用于计算图的连通分量、在 Kruskal 最小生成树算法中检测环，以及处理网格连通类问题。
Union-find manages a collection of disjoint sets and supports "find" (which set an element belongs to, i.e. whether two elements are connected) and "union" (merging two sets into one). It is used to compute connected components, to detect cycles in Kruskal's minimum-spanning-tree algorithm, and for grid-connectivity problems.

什么是摊还分析？它与"平均情况分析"有什么不同？

What is amortized analysis, and how does it differ from average-case analysis?

摊还分析对整个操作序列的总代价取平均，用来分析"个别操作偶尔很贵、但整体代价可控"的数据结构，比如动态数组扩容或栈上的多次弹出。它与平均情况分析不同：摊还分析是对最坏情况下序列总代价给出确定性上界，而不是对随机输入求概率期望。
Amortized analysis averages the total cost over a whole sequence of operations, targeting structures where a single operation is occasionally expensive but the overall cost stays bounded — e.g. dynamic-array resizing or multipop on a stack. It differs from average-case analysis: it bounds the total cost of the worst-case sequence deterministically, rather than giving a probabilistic expectation over random inputs.

递归和栈有什么关系？

What is the relationship between recursion and the stack?

每次函数调用，计算机都会把返回地址和局部变量压入调用栈；递归调用同样如此，一层层压栈，直到基准情形开始返回，再逐层弹出。这就是为什么递归太深会“栈溢出”——栈空间耗尽。理解这一点也解释了为什么任何递归都能改写成显式栈的循环。
Every function call pushes the return address and local variables onto the call stack; recursive calls do the same, piling up until the base case returns and the stack unwinds layer by layer. That is why very deep recursion causes stack overflow—the stack runs out of space. This also explains why any recursion can be rewritten as a loop with an explicit stack.

为什么二分查找比顺序查找快得多？

Why is binary search so much faster than linear search?

二分查找每次比较都把搜索范围砍半，前提是数据已经排好序。范围从 n 缩小到 1 只需约 log₂n 次比较，所以十亿条数据也只要约30步，而顺序查找平均要查一半数据。这是“分治”思想最经典的例子。
Binary search halves the search range with every comparison, but the data must already be sorted. Shrinking n items down to one takes only about log₂n comparisons, so one billion items need only about 30 steps, while linear search averages half the list. It is the classic example of the divide-and-conquer idea.

随机化算法为什么能借助随机数"帮忙"？随机化快速排序是例子吗？

How can randomness help an algorithm? Is randomized quicksort an example?

随机化算法在执行中引入随机选择，把"某些输入特别慢"的最坏情况变成以极高概率不会发生的事件。随机化的快速排序随机选取主元，使任意输入都以很高的概率达到 O(n log n) 的期望运行时间，不再依赖输入是否已经有序。
Randomized algorithms make random choices during execution, turning worst-case inputs into events that almost never happen. Randomized quicksort picks the pivot randomly, so every input achieves O(n log n) expected running time with high probability, regardless of whether the input is already sorted.

二分查找的前提条件是什么？

What are the preconditions for binary search?

二分查找要求数据已经排好序，并且能随机访问任意位置。每次取中间元素比较，可把搜索范围缩小一半，因此只需约 log₂ n 步。若数据无序，必须先排序才能使用。
Binary search requires the data to be sorted and randomly accessible. Each step compares the middle element and halves the search range, so it needs about log₂ n steps. If the data is unsorted, you must sort it first.

递归和迭代有什么区别？

What is the difference between recursion and iteration?

递归是函数调用自身来分解问题，代码往往更直观。迭代是用循环重复执行，通常更省内存。两者常可互相改写，深度递归可能栈溢出。
Recursion solves a problem by a function calling itself, often making code clearer. Iteration repeats with a loop and usually uses less memory. They can often be rewritten into each other, but deep recursion may overflow the call stack.

分治法的核心思想是什么？

What is the core idea of divide-and-conquer?

分治法把大问题拆成几个结构相同的子问题，分别解决后再合并结果。它让复杂问题变得可管理，并常带来对数级的效率提升。归并排序和快速排序都是典型例子。
Divide-and-conquer splits a big problem into smaller subproblems of the same kind, solves them, then combines the results. It makes hard problems manageable and often yields logarithmic efficiency gains. Merge sort and quicksort are classic examples.
