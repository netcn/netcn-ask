什么是重构？

What is refactoring?

重构是在不改变软件外部行为的前提下，调整内部结构以提升可读性与可维护性，如提取函数、重命名、消除重复。它依赖充分的单元测试来保证改动不破坏功能。
Refactoring improves a program's internal structure without changing its external behavior—extracting functions, renaming, removing duplication—to boost readability and maintainability. It relies on solid unit tests to ensure nothing breaks.

持续集成（continuous integration）指的是什么实践？

What practice does continuous integration refer to?

持续集成要求开发者频繁（往往每天多次）把代码合并到主干，并自动触发构建与测试，以便尽早发现集成错误。该实践源自 Kent Beck 的极限编程，并由马丁·福勒在 ThoughtWorks 的同名文章中系统推广，可显著降低「集成地狱」风险并提升交付质量。它与持续交付/持续部署（Humble & Farley 2010）一起构成现代 DevOps 流水线的基础。
Continuous integration asks developers to merge code into the mainline frequently—often several times a day—and to trigger automated builds and tests so integration errors surface early. The practice grew out of Kent Beck's Extreme Programming and was systematized by Martin Fowler's article at ThoughtWorks, sharply reducing 'integration hell' and improving delivery quality. Together with continuous delivery/deployment (Humble & Farley, 2010) it forms the basis of modern DevOps pipelines.

什么是敏捷开发？

What is agile development?

敏捷开发强调小步快跑、持续交付与拥抱变化，通过短周期迭代和频繁反馈来应对需求不确定性。Scrum 和极限编程（XP）是常见落地框架。
Agile development emphasizes small, rapid steps, continuous delivery, and embracing change, using short iterative cycles and frequent feedback to handle uncertain requirements. Scrum and Extreme Programming (XP) are common frameworks.

瀑布模型（waterfall）与敏捷（agile）开发方法的主要区别是什么？

What is the main difference between the waterfall and agile development methods?

瀑布模型由罗伊斯在 1970 年描述，强调需求、设计、实现、测试按顺序线性推进，适合需求稳定的项目。敏捷以 2001 年《敏捷宣言》为代表，主张小步迭代、持续交付与拥抱变化，更适合需求易变的场景。二者权衡的是可预测性与灵活性，现代团队常混合使用。
The waterfall model, described by Royce in 1970, emphasizes sequential linear phases—requirements, design, implementation, testing—suiting projects with stable requirements. Agile, represented by the 2001 Agile Manifesto, favors small iterative steps, continuous delivery, and embracing change, fitting volatile requirements. They trade predictability against flexibility, and modern teams often blend them.

什么是版本控制？

What is version control?

版本控制记录文件随时间的变化，让多人能并行修改并随时回到旧版本，常见工具有 Git。它像一份带时间戳的修改日记，避免改动互相覆盖。
Version control records how files change over time, letting many people edit in parallel and revert to old versions; common tools include Git. Like a timestamped change log, it prevents edits from overwriting each other.

什么是持续集成？

What is continuous integration?

持续集成要求开发者频繁把代码合并到主干，并由自动化构建和测试立即验证，尽早发现集成错误。它减少了集成地狱，是 DevOps 实践的重要一环。
Continuous integration has developers frequently merge code into the main branch, immediately verified by automated builds and tests to catch integration errors early. It reduces integration hell and is a key part of DevOps practice.

为什么说『向落后的软件项目增加人手，反而会让它更落后』？

Why is it said that adding people to a late software project makes it later?

布鲁克斯在 1975 年的《人月神话》中提出：软件项目的工作量不等于人数乘以时间，新增成员需要时间上手且加剧了沟通成本，因此赶工期时加人往往适得其反。他同时指出软件本质的复杂性没有『银弹』可一举解决。这部著作是软件工程管理领域的经典。
In 'The Mythical Man-Month' (1975), Brooks argued that software effort is not simply people times time: new members need ramp-up time and add communication overhead, so adding staff to catch up often backfires. He also argued there is no single 'silver bullet' for software's essential complexity. The book is a classic of software engineering management.

什么是软件工程？

What is software engineering?

软件工程是用系统化、可度量的方法开发、运行和维护软件的学科，关注质量、成本与进度。它涵盖需求分析、设计、编码、测试到运维的完整生命周期。
Software engineering is the disciplined, measurable approach to developing, running, and maintaining software, concerned with quality, cost, and schedule. It spans the full life cycle from requirements, design, coding, and testing to operations.
