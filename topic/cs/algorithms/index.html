快速傅里叶变换（FFT）为什么重要？它把什么运算从平方级降到对数级？

Why is the Fast Fourier Transform important, and what does it speed up?

快速傅里叶变换将离散傅里叶变换（DFT）的复杂度从朴素的 O(n²) 降到 O(n log n)，使大规模信号与多项式运算变得可行。库利与图基在 1965 年提出这一算法，其思想早由高斯萌芽。它广泛用于数字信号处理、音频图像压缩、大整数乘法和科学计算。
The Fast Fourier Transform reduces the discrete Fourier transform from a naive O(n²) to O(n log n), making large-scale signal and polynomial operations practical. Cooley and Tukey published the algorithm in 1965, though its idea traces back to Gauss. It is widely used in digital signal processing, audio/image compression, large-integer multiplication, and scientific computing.

P=NP 这个问题到底在问什么，为什么这么重要？

What exactly does P = NP ask, and why is it so important?

P 是能在多项式时间内求解的问题类，NP 是能在多项式时间内验证解的问题类；P=NP 问的是『易验证是否就等于易求解』。Cook 在 1971 年提出 NP 完全概念，若 P=NP 成立，大量密码学、优化与搜索难题将被轻易破解。
P is the class solvable in polynomial time, NP the class whose solutions are verifiable in polynomial time; P=NP asks whether easy-to-verify equals easy-to-solve. Cook introduced NP-completeness in 1971; if P=NP held, many cryptographic, optimization, and search problems would become trivial.

A* 算法比 Dijkstra 快在哪里，启发函数要满足什么条件才不会算错？

Where does A* beat Dijkstra, and what must its heuristic satisfy to keep results correct?

Dijkstra 按已付出代价 g(n) 由小到大均匀向四周扩展，完全不知道终点在哪；A* 改用 f(n)=g(n)+h(n) 排序，h 估计剩余距离，于是搜索前沿被拉向目标，在大地图上展开的节点数可以少一到两个数量级。正确性条件是 h 可采纳，即对任意节点都不高估真实剩余最短代价，此时 A* 保证给出最优解；若进一步满足一致性 h(n) ≤ c(n,n') + h(n')，每个节点只需展开一次，已关闭的节点不会被重开。h 恒为 0 时 A* 退化成 Dijkstra，h 高估则搜得更快但可能返回次优路径，这正是游戏寻路里加权 A* 的取舍。
Dijkstra expands nodes in increasing order of the cost already paid, g(n), spreading uniformly in every direction with no notion of where the goal lies; A* orders by f(n) = g(n) + h(n), where h estimates the remaining distance, which pulls the frontier toward the target and can cut expanded nodes by one or two orders of magnitude on large maps. Correctness requires h to be admissible, never overestimating the true remaining cost, which guarantees an optimal solution; if h is additionally consistent, satisfying h(n) ≤ c(n, n') + h(n'), each node needs expanding only once and closed nodes never reopen. With h identically zero A* degenerates into Dijkstra, while an overestimating h searches faster but may return a suboptimal path, precisely the trade-off weighted A* makes in game pathfinding.

Dijkstra 最短路径算法是什么？

What is Dijkstra's shortest path algorithm?

Dijkstra 算法用于求图中从单一起点到所有其他点的最短路径，要求边权非负。它不断选取当前距离最小的未访问节点，松弛其邻居的距离。时间复杂度依赖实现，使用优先队列时为 O((V+E) log V)。
Dijkstra's algorithm finds the shortest paths from a single source to all other vertices in a graph with non-negative edge weights. It repeatedly selects the unvisited node with the smallest current distance and relaxes the distances of its neighbors. Its complexity depends on the implementation; with a priority queue it is O((V+E) log V).

动态规划与分治法的本质区别在哪里？

What is the essential difference between dynamic programming and divide-and-conquer?

分治把问题拆成互不重叠的子问题分别求解；动态规划面对的是子问题大量重叠的情形，于是把算过的子问题结果存起来复用，用“以空间换时间”避免指数级重复计算。最优子结构加重叠子问题是它生效的前提。
Divide-and-conquer splits into non-overlapping subproblems solved separately; dynamic programming faces heavily overlapping subproblems, so it stores and reuses results—trading space for time to avoid exponential recomputation. Optimal substructure plus overlapping subproblems are its prerequisites.

P 与 NP 问题说的是什么？什么是 NP 完全（NP-complete）？

What does the P vs NP question ask, and what does NP-complete mean?

P 是能在多项式时间内求解的判定问题集合，NP 是能在多项式时间内被验证解的问题集合；P 是否等于 NP 是计算机科学最著名的未解难题之一，位列克莱数学研究所千禧年难题。NP 完全问题是一类最坏情况下最难、但解可快速验证的问题（如旅行商判定、布尔可满足性），由库克于 1971 年正式定义，卡普在 1972 年给出 21 个经典归约实例。
P is the set of decision problems solvable in polynomial time, while NP is the set whose solutions can be verified in polynomial time; whether P equals NP is among the most famous open problems in computer science and a Clay Millennium Prize Problem. NP-complete problems are the hardest in NP and have quickly verifiable solutions (e.g., SAT, the traveling-salesman decision problem), formally defined by Cook in 1971 and expanded by Karp's 1972 list of 21 reductions.

KMP 算法凭什么把字符串匹配做到线性时间，它省掉的到底是什么工作？

How does the KMP algorithm reach linear-time string matching, and what work does it eliminate?

朴素匹配在某一位失配后把主串指针整体回退一格重新比对，最坏情况（例如在一长串 a 里找 aaab）要做 O(nm) 次字符比较，大量比较是在重复已知的信息。KMP 先对模式串预处理出失配函数，记录每个前缀的最长真后缀同时也是前缀的长度；在模式第 j 位失配时，它据此知道已匹配部分有多少可以直接复用，于是把模式向右滑到那个偏移，主串指针永不后退。因为主串指针单调前进最多 n 步，模式指针的总回退量又被同一张表摊还限制在 O(m)，整体时间是 O(n+m)，额外空间 O(m)。
Naive matching backs the text pointer up by one position after every mismatch and recompares, costing O(nm) character comparisons in the worst case — searching for aaab inside a long run of a's, for instance — and most of those comparisons merely rediscover what was already known. KMP preprocesses the pattern into a failure function recording, for each prefix, the length of its longest proper suffix that is also a prefix; on a mismatch at pattern position j it therefore knows how much of the matched prefix can be reused and slides the pattern to exactly that offset, so the text pointer never moves backwards. Since the text pointer advances monotonically at most n times and the pattern pointer's total retreat is amortized to O(m) by that same table, the search runs in O(n + m) time with O(m) extra space.

红黑树是怎么保持“平衡”的？

How does a red-black tree stay 'balanced'?

红黑树给每个节点染红或黑，并强制几条规则：根黑、红节点不相邻、从任一节点到叶子的黑节点数相同。这些约束保证最长路径不超过最短的两倍，从而插入删除后只需少量旋转与变色就能维持近似平衡，保证操作 O(log n)。
A red-black tree colors nodes red or black under rules: root black, no adjacent reds, equal black-count on every path. This keeps the longest path at most twice the shortest, so insert/delete need only a few rotations and recoloring to stay balanced at O(log n).

A* 搜索相比 Dijkstra 多了什么使其更聪明？

What does A* add over Dijkstra to make it smarter?

A* 在 Dijkstra 的『已花代价』之外引入一个启发式函数，估计从当前节点到目标的剩余代价，优先扩展『已花+预计』最小者，从而少走弯路。只要启发式不高估真实代价（可采纳），它就能保证找到最优路径且更快。
A* augments Dijkstra's cost-so-far with a heuristic estimating remaining cost to the goal, expanding the node with the smallest (spent + estimated) total. As long as the heuristic never overestimates (admissible), it still finds the optimal path but explores far less.

什么是旅行商问题？

What is the traveling salesman problem?

旅行商问题要求在访问一系列城市各一次后回到起点，使总路程最短。它是经典的组合优化难题，属于 NP-hard，随着城市增多可行解数量呈阶乘级爆炸，常用近似算法、分支定界或启发式方法求解。
The traveling salesman problem asks for the shortest route that visits each of a set of cities exactly once and returns to the start. A classic combinatorial optimization problem, it is NP-hard, and the number of feasible tours grows factorially with the number of cities, so approximation, branch-and-bound, or heuristics are typically used.

什么是分治法？

What is divide and conquer?

分治法将大问题拆成若干规模更小、性质相同的子问题，递归求解后再合并结果。归并排序、快速排序和最近点对都采用这一策略，通常能把朴素 O(n²) 的问题降到 O(n log n)。
Divide and conquer breaks a problem into smaller subproblems of the same kind, solves them recursively, then combines the results. Merge sort, quicksort, and closest-pair all use this strategy, often reducing a naive O(n²) problem to O(n log n).

并查集（union-find）的“按秩合并”和“路径压缩”有什么用？

What do 'union by rank' and 'path compression' do for union-find?

并查集用来管理“哪些元素属于同一组”。按秩合并把矮树挂到高树下，避免树退化成链；路径压缩在查找时把节点直接连到根，压平树高。两者合用使每次操作近乎常数时间。
Union-find tracks which elements share a group. Union by rank attaches the shorter tree under the taller to avoid chains; path compression links nodes straight to the root during find, flattening the tree. Together they make each operation nearly constant.

什么是二分查找？它为什么比逐个查找快？

What is binary search and why is it faster than checking one by one?

二分查找在已排序的列表中每次都取中间项比较，丢掉一半不可能的范围，所以查找次数随数量对数增长，远少于逐个查找。
Binary search picks the middle item of a sorted list each time and discards half the candidates, so the number of steps grows logarithmically rather than linearly.

Dijkstra 最短路径算法是如何保证找到最短距离的？

How does Dijkstra's shortest-path algorithm guarantee the shortest distance?

在边权非负的图上，它每次从尚未确定的节点中挑选当前距离最小的，将其『锁定』为最终值，再松弛其邻居。这样每锁定一个节点，其距离已是全局最优。Dijkstra 在 1959 年发表该法。
On a graph with non-negative edge weights, it repeatedly picks the unconfirmed node with the smallest tentative distance, fixes it as final, and relaxes its neighbors; once fixed, that distance is globally optimal. Dijkstra published it in 1959.

快速排序(Quicksort)为什么平均比很多排序算法快？

Why is quicksort on average faster than many other sorting algorithms?

快速排序用分治法：选一个基准把数组分成比它小和比它大的两部分，再递归处理，平均时间复杂度仅 O(n log n) 且常数因子很小、缓存友好。Hoare 在 1961 年提出这一算法，它也是许多语言标准库默认的内省排序基础。
Quicksort uses divide-and-conquer: pick a pivot, partition into smaller and larger parts, then recurse; its average time is O(n log n) with a small constant and good cache behavior. Hoare introduced it in 1961 and it underlies many standard-library introsort implementations.

基于比较的排序算法为什么注定快不过 O(n log n)?

Why are comparison-based sorting algorithms doomed never to beat O(n log n)?

因为n个元素共有n!种可能排列,比较排序必须逐一区分它们,而每次比较只产生两种分支。把执行画成二叉决策树:内部节点是一次比较,叶子是判定结果,n!种输入要求至少n!片叶子;高度为h的二叉树至多2^h片叶子,故最坏比较次数不低于log₂(n!),按斯特林公式约为n·log₂n减线性项。归并排序与堆排序恰落在这一下界上,已属渐近最优;想更快只能绕开比较模型,比如计数排序利用键的取值范围。
Sorting n elements means telling apart n-factorial possible orderings, and each comparison yields only a two-way branch. Picture the algorithm as a binary decision tree: internal nodes are comparisons, leaves are verdicts, and covering all n! inputs demands at least n! leaves. A binary tree of height h has at most 2^h leaves, so worst-case comparisons sit at or above log2(n!) — roughly n log n minus a linear term by Stirling's formula. Merge sort and heapsort land exactly on this bound and are asymptotically optimal; going faster means abandoning the comparison model altogether, as counting sort does by exploiting key ranges.

动态规划凭什么能把指数爆炸的递归压缩成多项式时间?

What lets dynamic programming collapse exponentially exploding recursion into polynomial time?

关键在一个词:复用。朴素递归会反复求解同一个子问题,调用量随规模指数膨胀——直接按定义求斐波那契第n项约需1.618^n次调用;动态规划察觉这些子问题高度重叠、且最优解可由子问题的最优解组合而成,于是用一张表缓存答案,自顶向下记忆化或自底向上按依赖顺序填表,保证每个子问题只算一次。总复杂度变为子问题总数乘以单个子问题的开销,斐波那契就此降到O(n)。动规是否适用,正看重叠子问题与最优子结构这两张门票。
One word: reuse. Naive recursion solves identical subproblems over and over, so calls explode exponentially — deriving the nth Fibonacci number straight from the definition takes about 1.618^n function calls. Dynamic programming notices that these subproblems overlap heavily and that optimal solutions assemble from optimal subsolutions, so it caches every answer in a table, memoized top-down or filled bottom-up in dependency order, ensuring each subproblem is computed once. Total cost becomes the number of subproblems times the cost of solving one, dropping Fibonacci from exponential to linear time. Overlap plus optimal substructure is precisely the two-ticket test for whether dynamic programming applies.

电脑怎么在一堆数字里找出最大的那个?它比人找得快吗?

How does a computer find the biggest number in a pile — faster than people?

它用最朴素的办法:把数字排成一排,从第一个开始记住目前最大,逐个往后比较,遇到更大的就换记忆。一百个数字只要比九十九次,一眨眼完成。人一次能看一排,电脑一次只看一个,但每秒能做几十亿次,快就快在这里。
It uses the simplest plan: line numbers up, remember current champion, compare one by one, swap when a bigger appears. A hundred numbers need ninety-nine comparisons — done in a blink. People see rows at once while computers see one number at a time but compare billions per second.

二分查找为什么要求数据必须已经排好序？

Why does binary search require the data to be already sorted?

二分查找每一步都取中间元素与目标比较，据此砍掉一半区间；这个『砍半』的推理前提是剩下的区间里目标要么在左要么在右，只有有序才能保证。若无序，丢掉的那一半里可能正藏着答案。
Each step of binary search compares the middle element and discards half the range; that halving only works if the discarded half provably cannot contain the target, which requires order. On unsorted data the discarded half might hold the answer.
