为什么显卡的显存带宽常常比显存容量更能决定实际性能？

Why does a GPU's memory bandwidth often decide real performance more than its memory capacity?

GPU 有成千上万个并行线程，其算力（每秒浮点运算次数）增长远快于显存带宽（每秒字节数），因此大量真实内核落在带宽受限区间：判据是算术强度，即每搬运一个字节做多少次浮点运算，当它低于芯片的浮点每字节比值时，速度由带宽而非算力决定。屋顶线模型把这两条限制画成一条折线，一眼就能看出内核处在带宽斜坡还是算力平台上。容量只决定模型或数据集能不能装下，装下之后再多也不会更快，这也是大模型推理格外看重 HBM 带宽、而优化手段集中在算子融合、分块与提高数据复用的原因。
A GPU runs thousands of parallel threads and its arithmetic throughput in floating-point operations per second has grown far faster than its memory bandwidth in bytes per second, so many real kernels sit in the bandwidth-bound regime: whenever arithmetic intensity — operations performed per byte moved — falls below the chip's flops-per-byte ratio, bandwidth rather than compute sets the speed. The roofline model plots both limits as one curve, making it immediately visible whether a kernel lies on the bandwidth slope or the compute ceiling. Capacity only determines whether a model or dataset fits at all, and beyond that extra gigabytes add no speed, which is why LLM inference is judged on HBM bandwidth and optimization focuses on operator fusion, tiling and data reuse.

CPU 的流水线（pipeline）为什么会“停顿”（stall）？

Why does a CPU pipeline 'stall'?

流水线把一条指令拆成取指、译码、执行等多级并行推进；当后一级需要前一级还没算出的结果（数据相关）、或遇到分支误判、或硬件资源冲突时，就必须插入空泡等待，这就是停顿，会降低指令吞吐。
A pipeline splits an instruction into fetch/decode/execute stages running in parallel; when a later stage needs a result not yet ready (data hazard), a mispredicted branch occurs, or resources clash, bubbles are inserted to wait—that's a stall, lowering throughput.

在 FPGA 设计中，为什么跨时钟域直接传输单比特信号可能出错？两级触发器同步器如何降低亚稳态风险？

In FPGA design, why can transferring a single-bit signal directly across clock domains go wrong, and how does a two-flip-flop synchronizer reduce the metastability risk?

当输入信号在触发器的建立—保持窗口内变化时，输出可能进入既非0也非1的亚稳态，并经过不确定时间后才稳定。异步时钟之间无法保证不违反该窗口。两级同步器让第一级的亚稳态有整整一个时钟周期衰减，第二级再采样时几乎必然已恢复为确定的0或1；失效率随时间指数下降，工程师据此计算同步器的平均无故障时间来评估可靠性。
If a signal changes inside a flip-flop's setup-hold window, its output may enter metastability: an invalid voltage halfway between levels that persists for an unpredictable time before settling. Unrelated clock domains guarantee nothing about avoiding that window. A two-flip-flop synchronizer gives the first stage nearly one full clock period to decay before the second stage samples it, so recovery is overwhelmingly likely; residual failure probability decays exponentially, and engineers derive a synchronizer MTBF from this decay to quantify reliability.

GPU 的 SIMT 执行模型是什么？

What is the SIMT execution model of a GPU?

SIMT（单指令多线程）让成百上千个轻量线程以“线程束（warp）”为单位，同一时刻执行同一条指令但操作不同数据，非常适合矩阵乘法等高度并行的任务；但当线程走不同分支时会串行执行，拖慢整体。
SIMT (single-instruction multiple-thread) runs thousands of light threads in warps, all executing the same instruction on different data—ideal for massively parallel work like matrix multiply. Divergent branches run serially, slowing things.

嵌入式系统的看门狗定时器如何防止程序跑飞?实际使用中有哪些常见误区?

How does a watchdog timer keep an embedded system from running wild, and what are common mistakes when using one?

看门狗是硬件递减计数器,主流程必须周期性喂狗(重载计数值);一旦程序死锁或跑飞导致无法按时喂狗,计数器归零便触发芯片复位,让系统回到已知初始态。典型误区是把喂狗分散到多个任务或中断里——某个任务卡死后其余代码仍在喂狗,故障被掩盖;正确做法是由统一监控逻辑确认各关键任务心跳后再集中喂狗。
A watchdog is a hardware down-counter the main flow must reload periodically ('kicking'); if the program deadlocks or runs away and misses the deadline, the counter hits zero and resets the chip into a known state. A typical mistake is kicking from several tasks or interrupts: one task hangs while the rest keep feeding the timer, masking the fault — the sound pattern is a single supervisor that verifies heartbeats of all critical tasks before kicking once.

嵌入式实时系统做可调度性分析时，为什么依据最坏情况执行时间（WCET）而不是平均执行时间？

In embedded real-time systems, why does schedulability analysis rely on worst-case execution time (WCET) rather than average execution time?

实时系统的正确性以是否满足截止期来定义，只要有一次运行超时就可能造成失效，因此分析必须覆盖所有执行路径而非典型路径。WCET 通过结合静态分析与测量上界给出可论证的时间保证；平均值会把中断、缓存扰动等长尾因素隐藏掉，用它排布调度会导致偶发超时。工程实践中通常拿 WCET 配合利用率界或响应时间分析来验证任务集可行。
Correctness in a real-time system means meeting every deadline, so analysis must bound all execution paths rather than the typical one; a single overrun can already count as failure. WCET combines static analysis with measured upper bounds to yield demonstrable timing guarantees, whereas averages hide long-tail effects like interrupts and cache perturbations that surface as sporadic misses. In practice engineers pair WCET with utilization bounds or response-time analysis to prove a task set feasible.

FPGA 是如何用查找表（LUT）实现任意布尔组合逻辑的？为什么说一个 6 输入 LUT 能表达任何最多含六个变量的布尔函数？

How does an FPGA implement arbitrary combinational Boolean logic with lookup tables (LUTs)? Why can a single 6-input LUT represent any Boolean function of up to six variables?

LUT 本质是一小块可写存储：函数的真值表被完整装入 64（即 2 的 6 次方）个存储单元，六个输入充当地址，读出的单元内容就是该输入组合下的函数值。由于真值表穷举了任何六变量函数的全部取值，单个 LUT 必然足以覆盖；更大规模的电路由成千上万个 LUT 经可编程互连组装。与 ASIC 把门电路固化在硅片中不同，这一结构依赖配置文件加载，灵活但面积与功耗开销更高。
A LUT is essentially a small writable memory: the function's complete truth table is loaded into 64 storage cells (2 to the power of 6), the six inputs serve as the address, and the cell read at that address is the function value. Since a truth table enumerates every output of any six-variable function, one LUT always suffices; larger circuits assemble thousands of LUTs through programmable interconnect. Unlike ASICs, where gates are hard-wired in silicon, this structure exists only once configuration is loaded - flexible but costlier in area and power.

How do RISC and CISC instruction sets differ?

分支预测是什么，猜错了会怎样？

What is branch prediction, and what happens when it's wrong?

CPU 遇到“如果……就……”这种判断时，会提前猜走哪条路并先算起来。猜对就省时间；猜错就得把已算的部分丢掉重来，这种“清空流水线”会让程序短暂变慢。
When hitting an 'if…then…' choice, the CPU guesses the path and computes ahead. A correct guess saves time; a wrong one discards the work and restarts, briefly slowing things down—a 'pipeline flush'.

同样是 USB-C 接口的线，为什么有的能外接 4K 显示器，有的只能充电？

Why can some USB-C cables drive a 4K monitor while others only charge?

USB-C 只规定了插头的机械形状，能力取决于线里实际接了哪些导线以及有没有内置电子标记芯片。仅充电线可能只接了电源和两根低速数据线，缺少高速差分对，因此无法承载 DisplayPort 替代模式的视频或 USB 3.2/4 的信号，而视频与高速传输需要四对高速通道齐全。功率同理：超过 3 安或 20 伏的供电必须靠电子标记向两端声明线材额定值，没有它就只能协商到低档功率。所以选购要看线上标注的具体协议与瓦数，而不是只看接口形状。
USB-C specifies only the connector's mechanical shape; what a cable can do depends on which wires are physically present and whether it carries an e-marker chip. A charge-only cable may include just power plus two low-speed data lines and omit the high-speed differential pairs, so it cannot carry DisplayPort Alt Mode video or USB 3.2/4 signalling, both of which need all four high-speed lanes. Power works the same way: anything above 3 A or 20 V requires the e-marker to declare the cable's rating to both ends, and without it the pair negotiates down to a lower tier. Buy by the printed protocol and wattage rating rather than by the plug shape.

缓存（cache）是什么，为什么它又快又小？

What is a cache, and why is it fast but small?

缓存是 CPU 旁边极近、极快但很贵的小存储器，用来放最近用过的数据，下次直接取就不用去慢吞吞的内存。因为它用昂贵的 SRAM 制造，所以容量做不大，只能在“快”和“大”之间取舍。
A cache is a tiny, super-fast, expensive memory next to the CPU holding recently used data, so the next fetch skips slow RAM. Built from pricey SRAM, it stays small—a trade-off between speed and size.
