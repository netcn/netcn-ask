C/C++ 里的「未定义行为」为什么比普通 bug 更危险？

Why is undefined behaviour in C/C++ more dangerous than an ordinary bug?

标准规定，一旦程序出现未定义行为（有符号整数溢出、数组越界、解引用空指针等），对整个程序的行为不作任何要求，编译器因此可以假定它绝不发生。优化器会据此删除看似多余的判断，例如把跟在一次解引用之后的 if (p == NULL) 检查整段消掉，使症状远离真正的出错点，甚至只在换编译器或提高优化等级后才显形。可靠做法是用 UBSan、ASan 等运行时检查，用 -fwrapv 这类选项钉住语义，并从源头拒绝依赖「看起来能跑」的写法。
The standard says that once a program exhibits undefined behaviour — signed overflow, an out-of-bounds access, dereferencing null — no requirement whatsoever is placed on the program's behaviour, so the compiler may assume it never happens. Optimizers exploit that assumption and delete tests that look redundant, for instance dropping an if (p == NULL) check that follows a dereference of p, which makes symptoms surface far from the real fault or only after switching compilers or raising the optimization level. The practical defences are sanitizers such as UBSan and ASan, flags that pin down semantics like -fwrapv, and never relying on code that merely seems to work.

什么是停机问题？为什么它不可解？

What is the halting problem, and why is it undecidable?

停机问题问：能否写一个程序，判断任意程序加输入会不会终止。图灵用对角线法证明不可能：假设存在这样的判定程序 H，构造程序 D 对自身调用 H 并故意取反行为，无论 H 判 D 停还是不停，D 都自相矛盾。因此没有任何算法能解决它。它是可计算性理论的基石，说明“可计算”不等于“可判定”。
The halting problem asks whether a program can decide if any given program plus input will halt. Turing proved it impossible via diagonalization: assume a decider H exists, build a program D that calls H on itself and deliberately inverts the answer—whether H says D halts or not, D contradicts itself. So no algorithm can solve it. It is a cornerstone of computability, showing “computable” is not the same as “decidable”.

协程（coroutine）和普通线程有何不同？

How do coroutines differ from ordinary threads?

协程是用户态的轻量“可暂停/恢复”的执行单元，切换由程序自己控制而非操作系统抢占，开销远小于线程。多个协程常跑在少量线程上，通过显式让出来协作，而非靠时间片。它非常适合高并发 I/O，如海量网络请求。
A coroutine is a lightweight, user-mode execution unit that can suspend and resume, with switching controlled by the program rather than preempted by the OS, so its overhead is far smaller than a thread's. Many coroutines often run on a few threads and cooperate by explicitly yielding rather than by time slices. It suits high-concurrency I/O such as huge numbers of network requests.

垃圾回收是怎么工作的？为什么程序不需要手动释放内存？

How does garbage collection work, and why don't programs need to free memory manually?

垃圾回收器自动找出不再被引用的对象并回收其内存。常见做法：引用计数（Python 为主）统计被引用次数，归零即回收；可达性分析（Java、Go 的标记-清除）从根集合出发遍历，未被到达的对象都是垃圾。为减少停顿，现代 GC 还有分代回收、并发标记等优化。手动管理（C/C++）更高效但容易泄漏或悬垂。
The garbage collector finds objects no longer referenced and reclaims their memory. Common strategies: reference counting (mainly Python) frees objects when their count hits zero; reachability analysis (mark-and-sweep, used by Java and Go) traverses from root references and collects everything unreachable. To reduce pauses, modern GCs add generational collection and concurrent marking. Manual management (C/C++) is efficient but prone to leaks and dangling pointers.

什么是类型系统？静态/动态、强/弱类型各指什么？

What is a type system? What do static/dynamic and strong/weak typing mean?

类型系统给变量和表达式规定数据种类（整数、字符串等），编译期检查的叫静态类型，运行时检查的叫动态类型。强类型禁止类型被随意混用（整数加字符串会报错），弱类型允许隐式转换（如“5”+3 得到“53”）。Rust、Java 是静态强类型；Python、JavaScript 是动态类型，其中 JS 常被视为弱类型。
A type system assigns kinds (integer, string, ...) to variables and expressions. Static typing checks at compile time; dynamic typing at runtime. Strong typing forbids mixing types freely (adding an integer and a string errors), while weak typing allows implicit conversions (so “5”+3 gives “53”). Rust and Java are statically strongly typed; Python and JavaScript are dynamically typed, with JS usually seen as weakly typed.

编译器为什么要专门优化循环？循环不变量外提是怎么做的？

Why do compilers target loops specifically, and how does loop-invariant code motion work?

程序绝大部分运行时间花在循环里，所以编译器用数据流分析识别循环结构并做变换。循环不变量外提把"每次迭代结果都不变"的计算移到循环外只算一次；此外还有归纳变量消除、循环展开、强度削减等优化。这些变换依赖数据流分析证明安全性（不改变可观察行为）与收益性（确实节省时间）。
Loops consume most of a program's runtime, so compilers use data-flow analysis to identify loop structure and apply transformations. Loop-invariant code motion hoists computations whose result is unchanged across iterations out of the loop to run once; other transforms include induction-variable elimination, loop unrolling and strength reduction. These rely on data-flow analysis to prove both safety (observable behavior unchanged) and profitability.

什么是元编程，它常用于哪些场景？

What is metaprogramming and where is it commonly used?

元编程指编写能“生成或操纵其他程序（或自身）”的代码，即在程序层面处理代码。例如用宏在编译期展开重复逻辑，或用反射在运行期动态查看和调用对象成员。它可减少样板代码、增强表达力，但过度使用会降低可读性和可调试性。
Metaprogramming means writing code that generates or manipulates other code, or itself, operating on programs at the code level. Examples include macros that expand repetitive logic at compile time and reflection that inspects or invokes object members at runtime. It cuts boilerplate and boosts expressiveness but, overused, hurts readability and debuggability.

什么是尾递归，它为什么重要？

What is tail recursion and why does it matter?

尾递归指递归调用出现在函数的最后一步，且返回值直接就是该调用的结果。支持尾调用优化的编译器可把它改写成循环，避免不断压栈，从而像迭代一样省内存。否则深度递归仍可能栈溢出，所以尾递归是把递归写法变得安全的技巧。
Tail recursion means the recursive call is the last step and its result is returned directly. Compilers with tail-call optimization can rewrite it as a loop, avoiding growing the stack and saving memory like iteration. Without it, deep recursion can still overflow, so tail recursion is a technique to make recursive code safe.

λ 演算和现代编程语言有什么关系？

What is the connection between lambda calculus and modern programming languages?

λ 演算是 20 世纪 30 年代提出的一种极简形式系统，只用“函数定义”和“函数应用”表达一切计算。它奠定了函数式编程的理论基础，匿名函数、闭包、高阶函数等概念都能在其中找到根源。许多语言把 λ 表达式作为一等公民特性直接吸收。
Lambda calculus is a minimal formal system from the 1930s that expresses all computation using only function definition and application. It founded the theory of functional programming, and concepts like anonymous functions, closures, and higher-order functions trace back to it. Many languages adopt lambda expressions directly as first-class features.

引用计数有什么局限，为什么会产生循环引用？

What are the limits of reference counting and why do circular references arise?

引用计数给每个对象记录有多少地方引用它，计数为零即回收，简单且回收及时。但它难以处理循环引用：A 引用 B、B 又引用 A，二者计数都降不到零，内存便泄漏。因此很多系统把引用计数与可达性分析（如追踪式 GC）结合使用。
Reference counting records how many places refer to each object and reclaims it when the count hits zero, which is simple and prompt. But it struggles with circular references: if A refers to B and B to A, neither count reaches zero and memory leaks. Many systems therefore combine reference counting with reachability analysis such as tracing GC.

现代编译器在优化代码之前,为什么通常要先把程序改写成 SSA(静态单赋值)形式?

Why do modern compilers usually rewrite programs into SSA (Static Single Assignment) form before optimizing?

因为单赋值让数据流显式化:每个变量只被赋值一次,控制流汇合处用 φ 函数合并取值,于是常量传播、死代码消除、公共子表达式删除等优化都可化为简单的稀疏规则,速度更快且更容易验证正确性。GCC(GIMPLE)、LLVM、V8 等主流实现都以 SSA 作为核心中间表示。
Single assignment makes data flow explicit: each variable is written exactly once and values are merged by phi functions at control-flow joins, so optimizations like constant propagation, dead-code elimination and common-subexpression elimination reduce to simple sparse rules that run fast and are easy to verify. GCC GIMPLE, LLVM and V8 all build their middle ends on SSA.

Hindley-Milner 类型推导是怎么"算出"类型的？let 多态为什么是关键？

How does Hindley-Milner type inference "compute" types, and why is let-polymorphism key?

推导本质是约束求解：给每个表达式设一个含类型变量的方程，用合一（unification）算法逐步实例化变量，无法合一就报类型错误。let 多态允许同一个定义在不同使用点被实例化为不同类型（例如空表 [] 可同时作为 [Int] 与 [Bool]），而 lambda 参数在推导中必须保持单一类型。这种"泛化只在 let 处发生"的规则，正是 HM 兼顾表达力与可判定推导的关键。
Inference is constraint solving: each expression yields equations over type variables, a unification algorithm instantiates them step by step, and a failure to unify is a type error. let-polymorphism lets one definition instantiate to different types at different uses (e.g. [] can be both [Int] and [Bool]), while lambda parameters must keep a single type during inference. This "generalize only at let" rule is why HM balances expressiveness with decidable inference.

什么是类型推导？为什么在 Haskell、Rust 里可以省略大部分类型声明？

What is type inference? Why can most type annotations be omitted in Haskell or Rust?

类型推导是编译器根据表达式如何使用来自动确定其类型，用户无需写出全部类型注解。Hindley-Milner 风格的类型系统能保证推导出的类型是最一般的类型，并且推导效率高。推导的本质是收集类型约束并做合一（unification）求解，遇到矛盾时报类型错误。
Type inference lets the compiler determine types from how expressions are used, so programmers can omit most annotations. Hindley-Milner-style type systems guarantee the inferred type is the most general one, and inference is efficient. Inference essentially collects type constraints and solves them by unification, reporting a type error when a contradiction arises.

CPython 的全局解释器锁为什么让多线程算不快？

Why does CPython's global interpreter lock prevent threads from speeding up computation?

GIL 是一把保护解释器内部状态（尤其是对象引用计数）的全局互斥锁，任何时刻只有一个线程能执行 Python 字节码，所以纯 Python 的 CPU 密集任务无法靠多线程利用多核。但线程在阻塞式 I/O、time.sleep 或调用主动释放 GIL 的 C 扩展（多数 NumPy 数值核、zlib 压缩）时会交出锁，因此 I/O 密集程序依然受益。绕开办法是改用 multiprocessing 进程池，或使用 Python 3.13 起按 PEP 703 提供的自由线程实验构建。
The GIL is a single mutex protecting interpreter internals — above all object reference counts — so only one thread executes Python bytecode at a time and CPU-bound pure-Python work cannot scale across cores with threads. Threads do release the GIL during blocking I/O, time.sleep, and inside C extensions that drop it such as most NumPy kernels and zlib, which is why I/O-bound programs still benefit from threading. The workarounds are multiprocessing or process pools, or the experimental free-threaded build shipped from Python 3.13 under PEP 703.

函数式编程和面向对象编程有什么不同？

How do functional programming and object-oriented programming differ?

Functional code eases concurrency and testing; OOP models real-world entities intuitively.

The cost is larger code and longer compile times, so compilers usually inline only small, hot functions, controlled by heuristics and optimization levels.

How do interpreters, JIT compilers and ahead-of-time compilers differ in how they run code?

并发和并行是一回事吗？

Are concurrency and parallelism the same thing?

不是。并发是“处理多个任务”，可以交替推进、宏观上同时；并行是“同时执行多个任务”，需要多核或多处理器。单核上只能并发，不能并行。与之相伴的问题是竞态：多线程同时读写共享变量，结果依赖执行顺序，需要用锁或原子操作保护。
No. Concurrency is dealing with many tasks, interleaved so they appear simultaneous; parallelism is executing many tasks at once, requiring multiple cores or processors. A single core can be concurrent but never parallel. A related hazard is the race condition: threads reading and writing shared variables produce order-dependent results, so locks or atomic operations are needed.

Unicode 和 UTF-8 是什么关系，网页上的「锟斤拷」这类乱码是怎么来的？

How do Unicode and UTF-8 relate, and where does garbled text like mojibake come from?

Unicode 是字符集，为每个字符分配一个码位，例如「中」是 U+4E2D；UTF-8 是把码位转成字节的编码方式，ASCII 占 1 字节、常用汉字占 3 字节。乱码出现在写入与读取所用编码不一致时：GBK 编码的字节被当成 UTF-8 解码会产生非法序列，被替换成 U+FFFD 替换字符；当这些 U+FFFD 以 UTF-8 存回（每个是字节 EF BF BD），再被按 GBK 解读时，EF BF / BD EF / BF BD 三段恰好对应「锟」「斤」「拷」，于是出现著名的「锟斤拷」。而显示成空心方框通常不是编码错误，而是字体缺少该字符的字形。在两端统一声明 UTF-8，如 HTTP 的 Content-Type 头与 HTML 的 meta charset，即可避免。
Unicode is a character set that assigns every character a code point, so 中 is U+4E2D, while UTF-8 is one way of turning code points into bytes: ASCII takes one byte and common Chinese characters take three. Mojibake appears when the encoding used to write differs from the one used to read — GBK bytes decoded as UTF-8 yield invalid sequences that become U+FFFD replacement characters, and when those replacement characters are stored back as UTF-8 (each U+FFFD is the bytes EF BF BD) and then re-read as GBK, the sequences EF BF, BD EF and BF BD map to the characters 锟, 斤 and 拷, producing the notorious garbage string. Hollow boxes usually mean something different: the decoding was fine but the font has no glyph for that character. Declaring UTF-8 consistently at both ends, in the HTTP Content-Type header and the HTML meta charset tag, prevents it.

编译器如何决定哪些变量放进寄存器?为什么说寄存器分配本质上是图着色问题?

How does a compiler decide which variables live in registers, and why is register allocation essentially a graph coloring problem?

编译器先做活跃变量分析:若两个变量在某点同时存活,就在干扰图中连一条边;给结点分配颜色即分配寄存器,k 种颜色对应 k 个通用寄存器,相邻结点异色意味着两者绝不冲突。一般的图 k 着色是 NP 完全问题,无法精确高效求解,故实际采用简化—溢出等启发式,放不下的变量溢出到栈槽并插入加载存储指令。
The compiler runs liveness analysis: whenever two values are live at the same program point they get an edge in the interference graph, and coloring nodes with k colors corresponds to assigning k machine registers, adjacent nodes always differing so values never collide. General k-coloring is NP-complete, so real compilers rely on simplify-and-spill heuristics, pushing leftover values into stack slots together with inserted loads and stores.

What does the lexing phase of a compiler do? How is it divided from parsing?

词法分析把源代码的字符流切分成一个个词法单元（token），如关键字、标识符、数字和运算符，同时过滤空白与注释。语法分析则在 token 流之上按文法规则识别语句结构、生成语法树。词法分析用正则表达式和有穷自动机实现，速度快、规则局部化。
Lexing splits the raw character stream of the source into tokens — keywords, identifiers, numbers, operators — while discarding whitespace and comments. Parsing then recognizes statement structure from the token stream and builds a syntax tree. Lexers are implemented with regular expressions and finite automata, making them fast and localized.

什么是抽象语法树（AST）？编译器为什么基于它工作而不是直接处理源代码文本？

What is an abstract syntax tree (AST)? Why do compilers work on it instead of raw source text?

AST 是源代码的树状表示，只保留程序的结构化语义，去掉括号、分号等语法噪音。它让语义分析、类型检查和代码生成等后续阶段在统一的树结构上工作，同时也是代码格式化、静态检查和 IDE 重构等工具的基础。
An AST is a tree representation of the source that keeps only the structural meaning, dropping syntactic noise such as parentheses and semicolons. It lets later phases like semantic analysis, type checking and code generation all operate on one uniform tree, and it also underpins formatters, static checkers and IDE refactoring tools.

宏（macro）与普通函数调用有什么本质区别？

What is the fundamental difference between a macro and an ordinary function call?

普通函数在运行时被调用，参数先求值再传入；宏在编译期展开，可以直接操纵和生成源代码，从而实现延迟求值、代码生成等能力，是元编程的核心形式。C 预处理器的宏做文本替换，而 Rust、Lisp 的宏工作在语法层面、更安全可控。
Functions are invoked at runtime with already-evaluated arguments; macros expand at compile time, directly manipulating and generating source code, enabling lazy evaluation and code generation — the heart of metaprogramming. C preprocessor macros perform textual substitution, while Rust and Lisp macros operate at the syntax level and are safer and more controllable.

静态类型语言和动态类型语言有何不同？

What is the difference between statically and dynamically typed languages?

静态类型语言在编译期就确定并检查变量类型，如 Java、C++、Rust，能在运行前发现类型错误。动态类型语言在运行时才确定类型，如 Python、JavaScript，写起来更灵活但某些错误要等到运行才暴露。二者各有取舍：前者更稳，后者更灵活。
Statically typed languages fix and check types at compile time, such as Java, C++, and Rust, catching type errors before running. Dynamically typed languages determine types at runtime, such as Python and JavaScript, offering flexibility but letting some errors surface only when executed. Each trades off safety against flexibility.

封装、继承、多态分别指什么？

What do encapsulation, inheritance, and polymorphism mean?

封装是把内部实现隐藏起来，只暴露必要接口，降低耦合。继承允许一个类基于另一个类扩展，复用已有行为。多态让同一接口在不同对象上有不同实现，调用者无需关心具体类型。三者是面向对象最常提及的三大特性。
Encapsulation hides internal implementation and exposes only needed interfaces, reducing coupling. Inheritance lets one class extend another and reuse its behavior. Polymorphism lets one interface have different implementations across objects, so callers need not know the concrete type. These three are the oft-cited pillars of OOP.

编译型语言和解释型语言有什么区别？

What is the difference between compiled and interpreted languages?

编译型语言先把整个源代码翻译成机器码再运行，如 C、Rust，启动快、运行效率高。解释型语言由解释器逐行边读边执行，如早期 Python、JavaScript，跨平台方便、开发灵活但运行稍慢。现代很多语言采用折中方案，先编译成中间字节码再在虚拟机中执行。
Compiled languages translate the whole source into machine code before running, such as C and Rust, giving fast startup and high efficiency. Interpreted languages are executed line by line by an interpreter, such as early Python and JavaScript, offering portability and flexibility at some runtime cost. Many modern languages compromise by compiling to intermediate bytecode run on a virtual machine.

What is object-oriented programming (OOP)?

面向对象编程把数据和操作数据的方法打包成“对象”，以对象为单元来组织程序。它强调用类来描述一类事物的结构与行为，让代码更贴近现实模型。常见好处是易于复用、扩展和维护。

函数式编程的核心思想是什么？

What is the core idea of functional programming?

函数式编程把计算看作数学函数的求值，强调用纯函数描述“做什么”而非“怎么改状态”。它倾向于不可变数据和避免共享可变状态，从而减少并发中的意外。典型语言有 Haskell、OCaml，以及多语言中的函数式特性。
Functional programming treats computation as the evaluation of mathematical functions and emphasizes describing what to do with pure functions rather than how to mutate state. It favors immutable data and avoids shared mutable state, reducing surprises in concurrency. Representative languages include Haskell and OCaml, and many languages offer functional features.
