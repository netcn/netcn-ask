A scheduling algorithm decides which ready task gets the CPU next, with strategies like first-come-first-served, round-robin, and priority scheduling, aiming for fairness and efficiency.

什么是分页（paging）？

What is paging?

分页把内存和硬盘都切成固定大小的页，按需把页在两者之间搬动，简化了内存管理并避免了外部碎片。
Paging divides memory and disk into fixed-size pages, moving them between the two on demand, simplifying management and avoiding external fragmentation.

页表（page table）和 TLB 是怎么协作实现虚拟内存的？

How do the page table and TLB cooperate to implement virtual memory?

CPU 发出虚拟地址，MMU 查页表把它翻译成物理地址；页表存在内存里、查找较慢，于是用一小块极快的 TLB 缓存最近的翻译结果。TLB 命中可瞬间完成，未命中才去查多级页表，可能还要处理缺页。
The CPU issues a virtual address; the MMU translates it via the page table in RAM, which is slow, so a tiny fast TLB caches recent translations. A TLB hit resolves instantly; a miss walks the multi-level page table and may trigger a page fault.

一致性哈希的"虚拟节点"解决什么问题？为什么能改善数据倾斜？

What problem do virtual nodes solve in consistent hashing, and why do they reduce data skew?

真实节点少且哈希位置分散不均匀时，环上各节点负责的弧段长短差异很大，造成数据严重倾斜。虚拟节点给每个物理节点复制出几十到几百个哈希位置散布在环上，使负载分布趋于均匀，还能按机器性能设置不同权重；节点增减时数据迁移也更平滑，Cassandra、Redis Cluster 等均采用此设计。
With few real nodes scattered unevenly on the ring, the arcs each node owns vary wildly, causing severe data skew. Virtual nodes give each physical node dozens to hundreds of hashed positions spread around the ring, smoothing the load distribution, and allow per-machine weights; adding or removing nodes migrates data more evenly. Cassandra and Redis Cluster adopt this design.

What are user mode and kernel mode?

CPU 用特权级区分两种模式：用户态运行普通应用、权限受限；内核态运行操作系统、可访问硬件与全部内存，敏感操作通过系统调用陷入内核以保障安全。
The CPU uses privilege levels: user mode runs apps with restricted rights; kernel mode runs the OS with full hardware and memory access, and sensitive ops trap into the kernel via system calls for safety.

What problem does virtual memory solve?

虚拟内存为每个进程提供独立的连续地址空间，并通过页表映射到物理内存，实现内存隔离、按需分页（只加载用到的页）以及用磁盘交换扩展可用内存。
Virtual memory gives each process a private contiguous address space mapped via page tables to physical RAM, enabling isolation, demand paging (load only used pages) and disk-backed expansion of memory.

Paxos 解决什么问题？为什么它需要 Prepare 与 Accept 两个阶段？

What problem does Paxos solve, and why does it need Prepare and Accept phases?

Paxos 让一组可能崩溃、消息可能丢失的节点对一个值达成共识，是分布式一致性协议的基石。Prepare 阶段用递增的提案编号询问并收集"多数派已接受的最大编号值"；Accept 阶段提交该值并由多数派接受。编号约束保证了安全性——绝不会出现两个不同值都被多数派接受的情况，即使部分节点失效也能继续推进。
Paxos makes a set of crash-prone, message-losing nodes agree on a single value — the foundation of distributed consensus protocols. The Prepare phase uses increasing proposal numbers to gather the highest-numbered value already accepted by a majority; the Accept phase commits that value to a majority. The numbering discipline guarantees safety — two different values can never both be accepted by majorities — and progress continues despite partial failures.

Raft 用哪些机制让共识算法更易理解？它是怎么选出领导者的？

What mechanisms make Raft easier to understand, and how does it elect a leader?

Raft 把共识拆成领导选举、日志复制、安全性三个相对独立的子问题，并引入强领导者、任期号、日志匹配、选举限制等简化规则。节点处于跟随者/候选者/领导者三态：跟随者超时未收到心跳就转为候选者，递增任期号并请求投票，获得多数票即当选。任期号保证任何时刻至多一个有效领导者，投票限制保证日志的完整性。
Raft decomposes consensus into leader election, log replication and safety, adding simplifying rules such as a strong leader, term numbers, log matching and election restrictions. Nodes are followers, candidates or leaders: a follower that times out without a heartbeat becomes a candidate, bumps its term, requests votes, and wins with a majority. Terms ensure at most one valid leader at any time, and voting restrictions preserve log integrity.

一致性哈希解决了传统"取模哈希"在节点增删时的什么问题？

What problem with hash-modulo distribution does consistent hashing solve when nodes are added or removed?

传统的 hash(key) mod n 在节点数 n 变化时几乎要迁移全部键。一致性哈希把键和节点都映射到同一个环上，每个键归属于环上第一个遇到的节点；节点增删只影响环上相邻的一小段，通常只有约 1/n 的键需要迁移，因此非常适合缓存和分布式存储的动态扩容。
With hash(key) mod n, changing the node count n migrates almost every key. Consistent hashing maps both keys and nodes onto one ring, assigning each key to the first node encountered; adding or removing a node affects only a small neighboring arc, so typically only about 1/n of keys migrate — ideal for caches and distributed storage under dynamic scaling.

A system call is the controlled interface by which user programs request kernel services (file I/O, process creation); it traps from user mode into kernel mode via interrupt and returns after execution.

Docker 容器和虚拟机的主要区别是什么？为什么容器启动更快？

What is the main difference between Docker containers and virtual machines? Why do containers start faster?

虚拟机通过 Hypervisor 虚拟出整套硬件并运行一个完整的客户操作系统；容器则共享宿主机的内核，用命名空间（namespace）隔离进程视图、用 cgroups 限制资源，只打包应用及其依赖。容器没有启动内核的开销，因此秒级启动、资源占用更小，但隔离性弱于虚拟机。
Virtual machines emulate a full set of hardware and run a complete guest operating system via a hypervisor; containers share the host kernel, isolating process views with namespaces and limiting resources with cgroups, packaging only the application and its dependencies. Without the cost of booting a kernel, containers start in seconds and use fewer resources, though their isolation is weaker than a VM's.

写时复制（copy-on-write）是怎么优化 fork 的？

How does copy-on-write optimize fork?

fork 创建子进程时并不立即复制整个内存，而是让父子共享同一份物理页并标记为只读；只有当某一方真正写入某页时，才复制那一页。这样大多数 fork 几乎零拷贝，极大加快进程创建。
fork doesn't copy memory immediately; parent and child share pages marked read-only, and only when one writes a page is that page actually copied. Most forks thus cost almost nothing, speeding up process creation.

死锁产生的四个必要条件是什么？

What are the four necessary conditions for a deadlock?

互斥、持有并等待、不可剥夺、循环等待，四者同时成立才会死锁。只要打破任意一个（例如强制按序申请资源、允许抢占），就能防止死锁发生。
Mutual exclusion, hold-and-wait, no preemption, and circular wait must all hold for a deadlock. Breaking any one—e.g. ordering resource requests or allowing preemption—prevents it.

MapReduce 把大规模数据处理拆成哪两个阶段？它适合什么样的任务？

Into which two phases does MapReduce split large-scale data processing, and what tasks suit it?

MapReduce 先由 Map 阶段对每个数据块并行处理并产生中间键值对，再由 Reduce 阶段把相同键的值聚合。系统自动处理分片、调度、容错和排序，适合计数、统计、排序这类可以"分而治之"的批处理任务；需要多次迭代和共享状态的任务（如图计算）则效率不高。
MapReduce first runs a Map phase that processes each data block in parallel, emitting intermediate key-value pairs, then a Reduce phase aggregates values sharing the same key. The framework handles partitioning, scheduling, fault tolerance and sorting, suiting batch jobs like counting, statistics and sorting that divide-and-conquer well; workloads needing many iterations and shared state, such as graph algorithms, fit it poorly.

CAP 定理指出：分布式系统在一致性（Consistency）、可用性（Availability）和分区容错性（Partition tolerance）中最多同时满足两个。网络分区无法避免，所以当分区发生时必须在一致性与可用性之间取舍，许多系统选择可用性优先，接受短暂的不一致，即最终一致。

Network partitions are unavoidable, so during a partition the system must choose between consistency and availability; many systems prefer availability and accept brief inconsistency — eventual consistency.

什么是写时复制（Copy-on-Write）？它为什么能让 fork() 几乎瞬间完成？

What is copy-on-write, and why does it make fork() nearly instantaneous?

fork() 不再立刻复制父进程的整个地址空间，而是让父子进程共享全部物理页，并把双方页表项改成只读。任何一方第一次写入某页时，MMU 触发保护性缺页异常，内核此时才复制这一页并恢复写权限。复制的开销从一次性付清整个空间，推迟到只为真正被写的页逐页支付；fork 后紧跟 exec 的常见场景中，多数页面根本无需复制。
fork() no longer duplicates the parent's entire address space up front; parent and child instead share every physical page, with both sets of page-table entries marked read-only. The first write to a shared page raises a protection page fault, and only then does the kernel copy that single page and restore write permission. Copying cost thus shifts from paying for everything at once to paying page by page for pages actually written - and when exec() follows immediately, most pages are never copied at all.

一次进程上下文切换时内核究竟做了什么?切换的主要开销其实在哪里?

What does the kernel actually do during a process context switch, and where does most of its cost really lie?

内核先挂起当前进程,把程序计数器、通用寄存器与状态标志保存到它的内核栈和进程描述符,再从就绪队列选出下一个进程,恢复其寄存器并切换页表基址(CR3),最后用中断返回指令回到用户态。看得见的开销只是这几微秒的保存与恢复;更大的隐性开销在于更换地址空间会冲刷 TLB 并污染缓存,新进程随后要为大量访存缺失买单。
The kernel suspends the current process, saving its program counter, general-purpose registers and status flags onto the kernel stack and process descriptor, then picks a ready task, restores its registers and switches the page-table base (CR3) before an interrupt-return instruction re-enters user mode. The visible cost is those few microseconds of save and restore; the hidden cost dominates, because changing address spaces flushes the TLB and pollutes caches, leaving the new process to pay for many memory misses afterward.

两阶段提交（2PC）如何保证多个数据库要么全部提交、要么全部回滚？

How does two-phase commit (2PC) make multiple databases all commit or all abort?

2PC 由一个协调者主导：第一阶段"准备"，协调者询问所有参与者能否提交，各参与者写准备日志并回复；第二阶段"提交/中止"，协调者根据所有回复统一决定，若全员可提交就广播提交，否则广播回滚。这保证了原子性，但协调者若发生故障，参与者可能长时间阻塞等待。
2PC is led by a coordinator: in the prepare phase it asks every participant whether it can commit, and each participant writes a prepare log and replies; in the commit/abort phase the coordinator decides based on all replies — commit only if everyone agreed, otherwise abort — and broadcasts the decision. This guarantees atomicity, but if the coordinator fails, participants may block indefinitely.

手机为什么会自己把切到后台的 App 关掉？

Why does a phone kill apps that you left running in the background?

手机内存有限，又不像桌面系统那样大量依赖交换分区，所以内存吃紧时系统必须主动回收。Android 的低内存守护进程按重要性给进程排序：前台 App 最后被杀，其次是仍可见的、承载服务的，最先被回收的是纯缓存的空进程，所以你切走后不再可见的 App 最容易被清掉。这也是应用必须在 onPause/onStop 里保存状态并支持恢复的原因，否则用户切回来会发现进度丢失。

Android's low-memory killer daemon ranks processes by importance — foreground apps last, then visible ones, then those hosting services, and cached empty processes first — so the app you just switched away from is the earliest candidate. That is why apps are expected to persist state in onPause/onStop and restore it later; otherwise the user comes back to find their progress gone.

电脑或手机出毛病时，为什么「重启一下」经常真的有用？

Why does restarting a computer or phone so often actually fix the problem?

长时间运行的程序会积累泄漏的内存、失效的缓存、没释放的锁和互相矛盾的内部状态，这些错误彼此纠缠，很难在不停机的情况下修好。重启把这一切丢弃，让系统回到经过充分测试的初始状态，所有资源重新分配，于是症状消失。软件工程里有意利用这一点的设计思路叫「仅崩溃软件」：把组件做成随时可安全重启、重要状态存在可恢复的存储里，用重启代替复杂的错误处理。
A process running for a long time accumulates leaked memory, stale caches, unreleased locks and inconsistent internal state, and those faults interact in ways that are very hard to repair while it keeps running. A restart discards all of it and returns the system to the well-tested state it was designed to begin from, with every resource freshly allocated, so the symptom disappears. Researchers turned this into a design principle called crash-only software: make components safe to restart at any moment, keep important state in recoverable storage, and use restart in place of intricate error handling.

All of those steps must happen one after another, which is why you wait, and an SSD or fast startup removes part of it.

fork 之后父子进程看起来各有一份完整的内存,为什么系统几乎一瞬间就完成了复制?

After fork, parent and child seem to own complete copies of the memory image, so how can the system finish duplicating it almost instantly?

因为系统并没有立刻复制整份内存。fork 只复制页表:两边映射同一批物理页并统一标成只读,耗时仅毫秒级;之后任何一方第一次写入某个共享页都会触发缺页异常,内核此时才分配新的物理页、复制内容,并把双方对应的页表项改回可写。这种写时复制机制让 fork 加 exec 的典型流程近乎零成本,也是内存去重等技术的基础。
Nothing is copied up front. fork duplicates only the page tables: both sides map the same physical frames, all marked read-only, which takes milliseconds. The first write from either side raises a page fault, and only then does the kernel allocate a fresh frame, copy the contents and turn both entries writable again. This copy-on-write scheme makes the classic fork-plus-exec pattern nearly free and underpins memory-deduplication techniques.
