分页（paging）与分段（segmentation）在内存管理上有什么不同？

How do paging and segmentation differ in memory management?

分页把物理和虚拟内存都切成固定大小的页与页框，消除了外部碎片、便于按需调页，但页内仍有内部碎片。分段按逻辑意义（代码、堆、栈）划分为大小可变的段，便于保护与共享，却容易产生外部碎片。x86 硬件同时提供两套机制，但现代操作系统普遍采用平坦段模型、实际依靠分页完成内存管理与保护——在 x86-64 长模式下分段已基本被禁用。
Paging divides both physical and virtual memory into fixed-size pages and frames, eliminating external fragmentation and enabling demand paging, though internal fragmentation remains within a page. Segmentation splits memory into variable-size logical segments (code, heap, stack) that ease protection and sharing but suffer external fragmentation. x86 hardware provides both mechanisms, yet modern operating systems use a flat segment model and rely on paging for memory management and protection—segmentation is largely disabled in x86-64 long mode.

什么是 inode，它存储了文件的哪些信息？

What is an inode and what information does it store about a file?

在类 Unix 文件系统中，inode 是描述一个文件（或目录）的元数据结构，存放权限、所有者、大小、时间戳以及指向数据块的指针。文件名保存在目录项里，与 inode 编号相关联，因此一个文件可有多个名字（硬链接）。删除文件实际是减少其链接计数，计数为零才真正释放空间。
In Unix-like file systems, an inode is the metadata structure describing a file or directory, holding permissions, owner, size, timestamps, and pointers to data blocks. The file name lives in a directory entry linked to the inode number, so a file can have several names (hard links). Deleting a file really just decrements its link count, and the space is freed only when that count reaches zero.

什么是优先级反转，1997 年火星探路者号为什么反复自动重启？

What is priority inversion, and why did the 1997 Mars Pathfinder keep resetting itself?

优先级反转指低优先级任务持有一把互斥锁，高优先级任务必须等这把锁；若中等优先级任务不断抢占低优先级任务，高优先级任务就被第三方间接无限期阻塞。探路者号上，高优先级的总线管理任务等待低优先级气象任务持有的共享数据锁，中优先级通信任务频繁运行使气象任务迟迟无法释放锁，看门狗判定总线任务超时便触发整机复位。JPL 远程上传补丁打开 VxWorks 互斥量的优先级继承选项，让持锁者临时升到等待者的优先级，问题即消除。
Priority inversion occurs when a low-priority thread holds a mutex that a high-priority thread needs while a medium-priority thread keeps preempting the lock holder, so the high-priority thread is blocked indefinitely through a third party. On Pathfinder a high-priority bus management task waited on data shared with a low-priority meteorological task, medium-priority communications work starved the lock holder, and the watchdog saw the bus task miss its deadline and reset the spacecraft. Engineers at JPL uploaded a patch enabling VxWorks priority inheritance, which temporarily raises a lock holder to the waiter's priority and ended the resets.

Unix 文件系统里的 inode 记录的是什么，为什么它和文件名分离？

What does an inode record in a Unix file system, and why is it separate from the file name?

inode 保存文件的元数据与数据块指针（权限、大小、时间戳、磁盘位置），而文件名只存在于目录项里并指向 inode 编号。这样同一文件可有多个名字（硬链接），删除名字也不会立刻销毁数据。
An inode holds a file's metadata and data-block pointers—permissions, size, timestamps, disk location—while the name lives only in a directory entry pointing to the inode number. This lets one file have many names (hard links) and deletion not instantly destroy data.

死锁是怎么产生的，Dijkstra 的银行家算法如何避免它？

How does deadlock arise, and how does Dijkstra's banker's algorithm avoid it?

当多个进程各自占有部分资源又互相等待对方手里的资源，且形成循环等待时就会死锁。银行家算法在每次分配前模拟『若借出是否仍能保证所有人最终完成』，只在安全时才批准，从而预防死锁。
Deadlock occurs when processes each hold some resources and circularly wait for others'—a cycle of hold-and-wait. The banker's algorithm simulates before each grant whether everyone could still finish; it approves only if a safe state remains, preventing deadlock.

什么是系统颠簸（Thrashing）？

What is thrashing in an operating system?

颠簸指系统因物理内存不足而频繁进行页面换入换出，CPU 大量时间花在等待磁盘上，几乎无法执行有效任务。通常由多道程序度过高、页面置换算法不当引起，可通过工作集模型来缓解。
Thrashing happens when a system, short on physical memory, constantly swaps pages in and out, so the CPU spends most time waiting on disk and little on useful work. It is usually caused by too high a degree of multiprogramming or poor page replacement, and can be mitigated with the working-set model.

自旋锁在什么情况下比会睡眠的互斥锁更划算？

When is a spinlock a better choice than a sleeping mutex?

自旋锁让等待者在循环里反复检查锁标志而不放弃 CPU，代价是空转的时钟周期；互斥锁把线程挂起并触发上下文切换，代价通常在几微秒量级。若临界区极短、预期等待时间小于一次上下文切换的开销，且运行在多处理器上（单核自旋只会白等到时间片用完），自旋更划算。实际实现多用自适应策略：先自旋有限次数，超时后退化为睡眠等待，Linux 的自适应互斥量与 pthread 的 PTHREAD_MUTEX_ADAPTIVE_NP 都是这个思路。
A spinlock busy-waits on a flag without yielding the CPU, paying wasted cycles, while a mutex suspends the thread and pays a context switch typically measured in microseconds. Spinning wins when the critical section is very short, the expected wait is below that switch cost, and there are multiple cores — on a uniprocessor the spinner merely burns its whole time slice. Real systems use adaptive hybrids that spin for a bounded number of iterations and then block, as in Linux adaptive mutexes and pthread's PTHREAD_MUTEX_ADAPTIVE_NP.

什么是死锁？它发生的四个必要条件是什么？

What is deadlock, and what are its four necessary conditions?

死锁是一组进程互相等待对方持有的资源，永远无法前进。四个必要条件：互斥（资源同一时刻只能一个进程用）、持有并等待（占着资源还等别的）、不可抢占（资源不能被强行拿走）、循环等待（等待关系成环）。打破任一条件即可预防或解除，例如给资源统一编号并按序申请。
Deadlock is a set of processes each waiting on resources held by others, so none can proceed. The four necessary conditions: mutual exclusion (a resource used by one process at a time), hold and wait (holding resources while waiting for more), no preemption (resources cannot be forcibly taken), and circular wait (a waiting cycle). Breaking any condition prevents or resolves it—for instance, numbering resources and requesting them in order.

虚拟内存和分页是怎样让程序以为自己拥有整片连续内存的？

How do virtual memory and paging make a program think it owns a whole contiguous memory?

操作系统用页表把程序使用的虚拟地址映射到物理内存的页帧，缺页时再从磁盘换入；程序看到的只是一片统一、连续的地址空间。这样既隔离了进程，又让物理内存被灵活复用。
The OS uses a page table to map a program's virtual addresses to physical page frames, fetching from disk on a page fault; the program sees only one uniform, contiguous address space. This isolates processes and lets physical memory be reused flexibly.

页面置换算法（如 LRU）解决什么问题？

What problem do page replacement algorithms such as LRU solve?

当物理内存已满、又要调入新页时，操作系统必须挑一页换出到磁盘，页面置换算法决定换哪页。LRU（最近最少使用）假设最近很久没用的页将来也少用，优先换它，效果通常较好。理想算法需要知道未来，现实中常用近似 LRU 来权衡开销与命中率。
When physical memory is full and a new page must be brought in, the OS must choose a page to evict to disk, and the page replacement algorithm decides which. LRU (least recently used) assumes a page unused for a long time will stay unused and evicts it first, usually performing well. The ideal algorithm would know the future; in practice approximated LRU balances overhead and hit rate.

为什么普通程序崩溃不会拖垮整个操作系统？

Why doesn't a crashing application bring down the whole operating system?

CPU 提供用户态与内核态两种特权级别。应用程序跑在用户态，无法直接访问硬件和内核数据结构；一旦越界访问非法地址，MMU 会抛异常，操作系统接管并终止该进程，不影响其他进程。只有系统调用和中断才会切到内核态，由内核验证请求后执行。
CPUs provide user mode and kernel mode with different privilege levels. Applications run in user mode, unable to touch hardware or kernel data structures directly; any illegal access triggers an MMU fault, and the OS takes over to kill only that process. The CPU enters kernel mode only for system calls and interrupts, where the kernel validates and executes the request.

操作系统有哪些常见的进程调度算法？

What are common process scheduling algorithms in operating systems?

常见算法包括先来先服务、短作业优先、时间片轮转、优先级调度以及多级反馈队列等。时间片轮转给每个进程公平的小时间片，适合交互式系统；多级反馈队列则按行为动态调整优先级。各有侧重：有的追求吞吐，有的追求响应速度或公平。
Common algorithms include first-come first-served, shortest-job-first, round-robin, priority scheduling, and multilevel feedback queues. Round-robin gives every process a fair time slice and suits interactive systems, while multilevel feedback queues adjust priority by behavior. Each trades off throughput, response time, or fairness differently.

实时系统中低优先级的任务为什么会反过来拖住高优先级任务？火星探路者号当年的频繁重启，为何靠调整互斥锁的优先级策略就能根治？

In real-time systems, how can a low-priority task end up stalling a high-priority one, and why did switching the mutex's priority policy permanently fix the repeated resets aboard Mars Pathfinder?

高优先级任务因等待低优先级任务手中的互斥锁而被迫停摆，这种现象就是优先级反转。持锁者本该尽快跑完临界区交还锁，却被与锁无关的中优先级任务抢走CPU，锁迟迟无人释放，阻塞链越拖越长；火星探路者号正是因此屡屡触发看门狗，反复重启整个系统。引入优先级继承后，持锁任务被临时抬升到所有等待者中最高的优先级，迅速跑完临界区归还互斥锁，反转随即消失。
A high-priority task stalls because the mutex it needs is held by a low-priority task — that is priority inversion. The lock holder should finish its critical section quickly and hand the lock back, yet a medium-priority task needing no lock at all preempts it, so the mutex stays stuck and the blocking chain keeps growing; on Mars Pathfinder this repeatedly tripped the watchdog and rebooted the craft. With priority inheritance, the lock holder is temporarily boosted to the highest priority among everything waiting on it, races through its critical section and returns the mutex, and the inversion vanishes.

I/O 多路复用（如 select/poll/epoll）解决什么问题？

What problem does I/O multiplexing such as select/poll/epoll solve?

当程序要同时盯住大量网络连接或文件，却不想为每一个都开一个线程时，I/O 多路复用让一个线程同时监视多个描述符，哪个就绪就处理哪个。select/poll 每次都要扫描全部描述符，开销随数量线性增长；epoll 等则只返回就绪项，更适合海量连接。它用单线程高效支撑高并发服务。
When a program must watch many network connections or files at once without spawning a thread per item, I/O multiplexing lets one thread monitor multiple descriptors and handle whichever is ready. select/poll scan all descriptors each time, so cost grows linearly, while epoll and similar return only ready ones and suit huge numbers of connections. It lets a single thread efficiently support highly concurrent services.

什么是死锁？产生死锁的四个必要条件是什么？

What is a deadlock, and what are the four necessary conditions for one?

死锁是指两个或多个进程因相互等待对方持有的资源而永远无法继续执行的状态。科弗曼等人在 1971 年总结出四个必要条件：互斥、持有并等待、不可抢占、循环等待；只有四者同时成立才会出现死锁。打破其中任一条件（如资源有序分配、超时放弃）即可预防或避免死锁。
A deadlock is a state in which two or more processes are permanently blocked, each waiting for a resource held by another. Coffman et al. (1971) identified four necessary conditions: mutual exclusion, hold and wait, no preemption, and circular wait; a deadlock occurs only when all four hold. Breaking any one of them—for example, ordered resource allocation or timed rollback—prevents or avoids deadlock.

竞态条件发生在多个线程并发访问共享数据、且最终结果取决于执行时序时，常导致难以复现的错误。互斥锁通过对临界区加锁，保证同一时刻只有一个线程能进入，从而把并发访问串行化。配合信号量、条件变量等原语，操作系统和编程语言得以安全地协调并发。
A race condition arises when multiple threads access shared data concurrently and the final result depends on execution timing, often causing hard-to-reproduce bugs. A mutex locks a critical section so that only one thread can enter it at a time, serializing the concurrent access. Together with semaphores and condition variables, such primitives let operating systems and languages coordinate concurrency safely.

什么是僵尸进程？

What is a zombie process?

子进程结束后，其退出状态需由父进程通过“等待”系统调用回收；若父进程迟迟不回收，子进程就留下一个只占进程表项、不再运行但未被清除的僵尸进程。僵尸本身不消耗 CPU 和内存，但积累过多会耗尽进程号。让父进程正确回收，或父进程退出后由 init 接管，可消除它们。

A zombie consumes no CPU or memory, but too many can exhaust process IDs. Proper reaping by the parent, or letting init adopt it when the parent exits, removes them.

Kernel threads and init are protected, and the victim receives SIGKILL rather than SIGTERM, so it cannot flush state — which is why databases are commonly given a negative oom_score_adj.

信号量是由 Dijkstra 提出的同步原语，用一个可原子增减的整数表示可用资源数量。P 操作申请资源、V 操作释放资源，常用来解决多线程间的互斥与协作问题。
A semaphore, introduced by Dijkstra, is a synchronization primitive using an integer that can be changed atomically to represent available resources. The P operation acquires a resource and V releases it, commonly used for mutual exclusion and coordination among threads.

单片机让 CPU 逐字节搬运串口或 ADC 数据既慢又费时，把活儿交给 DMA 后处理器立刻腾出了手，DMA 到底替 CPU 包揽了什么？

On a microcontroller, having the CPU ferry UART or ADC bytes one at a time is slow and wasteful, yet delegating the job to DMA frees the processor almost instantly — what exactly does DMA take over for the CPU?

DMA 控制器接管了数据在内存与外设之间的搬运：CPU 只需设置一次源地址、目标地址和传输长度，之后的整个传送过程都不再占用处理器周期。配置完毕 CPU 立即返回，继续执行其他任务或进入休眠省电；外设就绪时发出请求，DMA 经总线仲裁直接成块读写，全部搬完才上报一次完成中断。原先逐字节触发的海量中断被压缩成整批一次，CPU 占用率骤降，实时响应与功耗同步改善，这正是它被称作片上搬运工的原因。
A DMA controller takes over shuttling data between memory and peripherals: the CPU programs a source address, a destination address and a transfer length once, and the whole move afterward consumes no processor cycles at all. Configuration done, the CPU immediately returns to other work or sleeps to save power; when the peripheral signals readiness, the DMA arbitrates for the bus and moves the block wholesale, raising a single completion interrupt once everything lands. Thousands of per-byte interrupts collapse into one batch notification, CPU load plummets, latency and energy improve together — hence its nickname, the chip's porter.

什么是上下文切换，它为什么有开销？

What is a context switch and why does it have overhead?

上下文切换指 CPU 从一个进程或线程转到另一个时，保存当前运行状态（寄存器、程序计数器等）并恢复下一个状态的过程。因为要读写内核数据、刷新相关缓存，且期间真正干活的指令变少，所以频繁切换会降低效率。
A context switch is when the CPU moves from one process or thread to another by saving the current run state (registers, program counter, etc.) and restoring the next one. Because it touches kernel data and flushes relevant caches while doing less useful work, frequent switching lowers efficiency.

分页（paging）是怎么管理内存的？

How does paging manage memory?

分页把物理内存和虚拟地址空间都切成固定大小的“页”，用页表记录虚拟页到物理页框的映射。程序按虚拟页号访问，硬件查表得到真实地址，从而允许物理内存零散分配而不必连续。它也方便了换页和内存保护。
Paging divides both physical memory and the virtual address space into fixed-size pages, with a page table recording the mapping from virtual pages to physical frames. The program addresses by virtual page number and the hardware looks it up to get the real address, allowing scattered physical allocation without needing contiguous memory. It also eases swapping and memory protection.

An operating system is system software that manages hardware resources (CPU, memory, disk, devices) and provides a runtime environment for programs, with duties including process scheduling, memory management, and file I/O. 电脑的「睡眠」和「休眠」到底有什么不一样？

What is the real difference between putting a computer to sleep and hibernating it?

睡眠对应 ACPI 的 S3 状态：CPU 停止、硬盘停转，但内存持续供电以保存现场，因此恢复只要一两秒，代价是一旦断电内容就丢失。休眠对应 S4 状态：系统把整个内存内容写进硬盘上的休眠文件后完全断电，恢复时再读回来，因此几乎不耗电但唤醒较慢，还需要与内存等量的磁盘空间。Windows 的快速启动是混合方案，只把内核会话写盘，速度和耗电都介于两者之间。
Sleep is ACPI state S3: the CPU halts and disks spin down, but RAM keeps drawing power to hold your session, so resume takes a second or two and everything is lost if power is cut. Hibernation is S4: the full memory image is written to a file on disk and the machine powers off completely, so it draws essentially nothing but wakes more slowly and needs disk space equal to installed RAM. Windows fast startup is a hybrid that hibernates only the kernel session, landing between the two in both speed and power draw.
