什么是尾递归优化？

What is tail-call optimization?

当递归调用是函数最后一步时，编译器可复用当前栈帧而非新建，把递归转为等价循环，避免深递归的栈溢出，函数式语言常依赖它。
When the recursive call is the last step, the compiler can reuse the current stack frame instead of adding one, turning recursion into a loop and avoiding stack overflow; functional languages rely on it.

什么是 CI/CD？它解决了什么问题？

What is CI/CD, and what problems does it solve?

CI（持续集成）指开发者的每次提交自动触发构建和测试，尽早暴露错误；CD（持续交付/部署）再把通过验证的产物自动发布到测试甚至生产环境。整套流水线由配置文件声明，跑在 Jenkins、GitHub Actions 等平台上。它消灭了“本地能跑、服务器不行”和手动发布出错两大痛点，让发布变成日常小事。
CI (continuous integration) automatically builds and tests every commit to surface errors early; CD (continuous delivery/deployment) then ships validated artifacts to staging or production automatically. The whole pipeline is declared in configuration files and runs on platforms like Jenkins or GitHub Actions. It eliminates “works on my machine” and error-prone manual releases, making deployment routine.

什么是内存对齐，为什么影响性能？

What is memory alignment and why does it affect performance?

CPU 按字长边界读取数据，未对齐的变量可能跨越两个缓存行，需要多次访问甚至触发硬件异常；合理对齐可提升访问速度并避免某些架构上的错误。
CPUs fetch data on word boundaries; misaligned variables may span two cache lines, needing extra accesses or causing faults on some architectures, so proper alignment improves speed and correctness.

设计模式是什么？为什么说它是对经验的抽象？

What are design patterns, and why are they called abstracted experience?

设计模式是反复出现的设计问题的成熟解决方案，由《设计模式》一书系统总结，例如单例保证全局只有一个实例，观察者让一个对象变化时自动通知多个依赖，工厂把对象的创建解耦。它不是可复制的代码，而是“结构怎么组织”的蓝图；滥用反而增加复杂度，所以要按需使用。
Design patterns are proven solutions to recurring design problems, catalogued in the “Gang of Four” book—for example, Singleton guarantees one global instance, Observer notifies many dependents automatically when a subject changes, and Factory decouples object creation. They are not copyable code but blueprints for how to structure solutions; overuse adds complexity, so apply them deliberately.

What are recursion and iteration, and how do they compare?

递归用函数自己调用自己表达问题，代码简洁但可能栈溢出；迭代用循环重复，通常更省内存、更易控制。
Recursion expresses problems via self-calls—clean but risks stack overflow; iteration uses loops—usually more memory-efficient and controllable.

什么是函数式编程？

What is functional programming?

函数式编程把计算视为数学函数的求值，强调不可变数据和纯函数（相同输入永远得到相同输出、无副作用）。它便于并行和推理，常见于 Haskell、Scala，也被现代语言以 lambda 等方式采纳。与面向对象编程是两种不同的思维方式。
Functional programming treats computation as evaluating mathematical functions, emphasizing immutable data and pure functions (same input always yields same output, no side effects). It eases parallelism and reasoning, seen in Haskell and Scala and adopted via lambdas in modern languages. It is a different mindset from object-oriented programming.

不变性（Immutability）为什么重要？

Why does immutability matter?

不可变数据创建后不能修改，能避免共享状态被意外篡改、简化并发安全并让变更可预测，函数式编程和 React 状态管理都大量依赖它。
Immutable data cannot be changed after creation, preventing accidental mutation of shared state, simplifying concurrency safety and making changes predictable—relied on by functional programming and React state.

垃圾回收（GC）是如何工作的？

How does garbage collection work?

GC 自动回收不再被引用的对象所占内存，常见有标记-清除和分代回收：先标记可达对象，再清除不可达对象，减少手动内存管理的错误。
GC automatically reclaims memory of unreachable objects; common schemes like mark-sweep and generational collection mark reachable objects then free the rest, reducing manual memory bugs.

开源许可证（如 MIT 和 GPL）有什么区别？

What is the difference between open-source licenses like MIT and GPL?

开源许可证规定代码怎么用、怎么改、怎么分发。MIT 宽松：几乎随便用，只要保留版权声明；GPL 是 copyleft：你分发修改版时必须开源并沿用 GPL，防止代码被私有化。选择许可证决定了代码生态的走向——宽松许可利于商业采用，copyleft 保护社区成果。
Open-source licenses define how code may be used, modified, and distributed. MIT is permissive: use it almost any way, just keep the copyright notice. GPL is copyleft: modified versions you distribute must also be open and under GPL, stopping privatization. Choosing a license shapes the ecosystem—permissive licenses invite commercial adoption, copyleft protects community work.

单元测试和集成测试有什么不同？

What is the difference between unit tests and integration tests?

单元测试针对最小的代码单位（函数、方法），用桩件隔离依赖，跑得快、出错定位准；集成测试验证多个模块、数据库或外部接口配合是否正常，发现的是接口不一致、环境差异等问题。好的测试金字塔是：大量单元测试垫底，少量集成测试居中，端到端测试最少。
Unit tests target the smallest units—functions and methods—isolated with stubs, running fast with precise failure locations; integration tests verify that modules, databases, and external APIs work together, catching mismatched interfaces and environment issues. A healthy test pyramid has many unit tests at the base, fewer integration tests in the middle, and the fewest end-to-end tests.

同步和异步编程有什么区别？

What is the difference between synchronous and asynchronous programming?

同步代码按顺序阻塞执行，一步完成才进行下一步；异步允许在等待 IO 等耗时操作时让出控制权去处理别的事，最终通过回调、Promise 或 async/await 取结果。
Synchronous code runs in order and blocks; asynchronous code yields control while waiting on slow tasks like I/O and resumes via callbacks, Promises or async/await, improving throughput.

什么是递归函数？

What is a recursive function?

递归函数是直接或间接调用自身的函数，常用于解决可分解为相同子问题的情况，如阶乘、斐波那契数列和树遍历。它必须设置终止条件，否则会无限循环直至栈溢出。递归往往代码简洁但需注意效率。
A recursive function calls itself directly or indirectly, often used for problems that split into identical subproblems, such as factorial, Fibonacci, and tree traversal. It must have a termination condition, or it loops forever until stack overflow. Recursion is often concise but needs attention to efficiency.

代码审查让另一位开发者阅读改动并给出意见，能提前发现逻辑错误、安全问题、可读性问题，也是团队知识传播的渠道——没人只懂自己写的模块。自动化工具查不到设计层面的问题，人的审查正好互补。研究发现审查过的代码缺陷率显著更低。
Code review has another developer read the changes and give feedback, catching logic bugs, security holes, and readability issues early, while spreading knowledge—nobody owns a module alone. Automated tools miss design-level problems, which human review complements. Studies find reviewed code has markedly fewer defects.

程序员说的bug是什么?第一个电脑bug真的是一只飞蛾吗?

What do programmers mean by a bug? Was the first computer bug really a moth?

程序错误俗称bug(虫子)。1947年哈佛Mark II计算机故障,工程师真的从继电器里揪出一只飞蛾贴进工作日志,写下发现第一只实际案例。从此bug成为行话,修错就叫debug。今天绝大多数bug是代码逻辑疏漏而非真虫子,但排查精神一脉相承:复现问题、缩小范围、定位修复、回归测试。
Program errors are commonly called bugs. In 1947 Harvard Mark II engineers pulled a real moth from a relay, taping it into the logbook labeled first actual case found — coining debug for fixing. Most bugs today are logic slips, not insects, yet the spirit persists: reproduce, narrow down, fix, retest.

为什么程序里不该用等号直接比较两个浮点数？

Why shouldn't a program compare two floating-point numbers for exact equality?

二进制浮点无法精确表示 0.1、0.2 这类十进制小数，每一步运算又按 IEEE 754 规则舍入，所以 0.1 加 0.2 的结果是 0.30000000000000004，与字面量 0.3 的位模式不同，相等判断因此失败。正确做法是判断两数之差的绝对值是否小于某个容差，且容差要随数值量级缩放，例如比较 abs(a-b) 与 eps 乘 max(abs(a), abs(b))。涉及金额时更应彻底放弃浮点，改用十进制类型或以整数分为单位，如 Python 的 decimal.Decimal。
Binary floating point cannot represent decimals like 0.1 or 0.2 exactly, and every operation rounds under IEEE 754, so 0.1 plus 0.2 yields 0.30000000000000004 whose bit pattern differs from the literal 0.3 and the equality test fails. The correct approach compares the magnitude of the difference against a tolerance that scales with the values involved, such as testing abs(a - b) against eps times max(abs(a), abs(b)), rather than a fixed epsilon. For money, abandon floats entirely and use a decimal type or integer minor units, for example Python's decimal.Decimal.

Git 是怎么管理代码版本的？

How does Git manage code versions?

Git 是分布式版本控制系统，把文件快照组织成有向无环图的提交链。每次 commit 都记录改动和作者信息；分支让多人并行开发，合并时自动三路合并，冲突需手动解决。因为每个开发者的本地都是完整仓库，无需中央服务器就能离线工作，也更易备份恢复。
Git is a distributed version control system that organizes file snapshots into a chain of commits forming a directed acyclic graph. Each commit records changes and authorship; branches let people develop in parallel, and merges apply three-way merging, with conflicts resolved by hand. Since every developer has a full local repository, you can work offline with no central server and recover easily.

明明多写了测试代码，为什么反而说开发速度更快？

If tests mean writing extra code, why do they make development faster?

缺陷发现得越晚，定位与修复成本越高：排查线上回归往往要翻日志、复现环境、协调发布，而单元测试能在几秒内把责任范围缩小到刚改动的那几行。有了一套可信的测试，重构和升级依赖时不必靠「小心一点」来保证不破坏功能，改动的心理成本大幅下降。测试驱动开发进一步把测试当成设计工具：先写一个会失败的测试来明确需求边界，再写最少的代码让它通过，然后重构。
The later a defect surfaces, the more it costs to locate and fix: chasing a production regression means digging through logs, reproducing an environment and coordinating a release, whereas a unit test narrows the blame to the lines you just touched within seconds. A trustworthy suite also removes the fear tax on refactoring and dependency upgrades, since correctness no longer depends on being careful. Test-driven development pushes further and treats tests as a design tool — write a failing test to pin down the requirement, write the least code that passes it, then refactor.
